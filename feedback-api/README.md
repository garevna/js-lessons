# Обратная связь

Вопрос, заданный на странице урока, попадает в закрытый телеграм-канал. Ответ
пишется там же — обычным ответом на сообщение (reply) — и появляется у читателя
под его вопросом, когда он снова откроет сайт. Админки нет и не будет: админка
— это место, куда вопросы приходят, чтобы остаться без ответа.

Регистрации тоже нет. Первый вопрос заводит тред, и браузер читателя хранит две
строки: короткий `id` треда — он печатается в телеграме, чтобы тред можно было
найти через полгода, — и длинный `token`, который из браузера никуда не уходит и
без которого тред не прочитать. Никто не придумывает пароль, никто не
подтверждает почту. Читатель, почистивший хранилище, просто начнёт новый тред:
это честная цена за то, что форма не спрашивает ничего.

## Что где лежит

| | |
|---|---|
| `src/index.js` | маршруты и проверки |
| `src/store.js` | две таблицы в D1 |
| `src/telegram.js` | отправка в канал и чтение ответа |
| `schema.sql` | сами таблицы |
| `set-webhook.js` | один раз сказать телеграму, куда слать ответы |

## Маршруты

| | |
|---|---|
| `POST /feedback` | `{ text, name?, page?, lang?, thread?, token? }` → `{ thread, token, id, delivered }` |
| `GET /feedback?thread=…&token=…&since=…` | переписка, старое первым |
| `POST /telegram` | вебхук; чужой сюда не постучится — проверяется секрет в заголовке |
| `GET /health` | жив ли и что из настроек не задано (сами значения не показываются) |

## Развернуть с нуля

Нужен бот (создаётся у [@BotFather](https://t.me/BotFather)) и закрытый канал,
в котором этот бот — администратор с правом писать.

**1. База.**

```
cd z:/js-lessons-gh-pages/feedback-api
npm install
npx wrangler login
npx wrangler d1 create js-lessons-feedback
```

Команда напечатает `database_id` — вписать его в `wrangler.toml`. Затем:

```
npm run schema
```

**2. Канал.** Узнать его id: переслать любой пост из канала боту
[@getidsbot](https://t.me/getidsbot). Это число вида `-1001234567890` — вписать
в `wrangler.toml`, в `TELEGRAM_CHAT_ID`. Оно не секретное: без токена оно
бесполезно.

**3. Секреты.** Вот это — секретное, и в файлы репозитория не попадает никогда:

```
npx wrangler secret put TELEGRAM_BOT_TOKEN        # токен от BotFather
npx wrangler secret put TELEGRAM_WEBHOOK_SECRET   # любая длинная строка, придумать
```

Команда спросит значение, отправит его в Cloudflare и обратно уже не покажет —
ни в панели, ни кому бы то ни было. Можно то же самое мышкой: Workers → воркер →
Settings → Variables and Secrets → Add → тип **Secret**.

**4. Деплой.**

```
npm run deploy
```

Вывод содержит адрес вида `https://js-lessons-feedback.<поддомен>.workers.dev`.

**5. Вебхук.** Телеграм не присылает ответы никуда, пока ему не скажешь куда.
Для этого шага скрипту нужен токен локально — положить рядом файл `.dev.vars`
(git его игнорирует):

```
TELEGRAM_BOT_TOKEN=123456:ABC...
TELEGRAM_WEBHOOK_SECRET=та-же-длинная-строка
```

и выполнить:

```
node set-webhook.js https://js-lessons-feedback.<поддомен>.workers.dev
```

Проверить в любой момент: `node set-webhook.js --info`.

**6. Проверка.** `curl https://…workers.dev/health` — покажет четыре галочки:
база, токен, канал, секрет вебхука. Потом отправить вопрос:

```
curl -X POST https://…workers.dev/feedback \
  -H "Content-Type: application/json" \
  -d '{"text":"проверка связи","page":"Classes","lang":"ua"}'
```

В канале появится сообщение; ответ на него (reply) ляжет в тред, и
`GET /feedback?thread=…&token=…` его покажет.

## Локально

```
npm run dev
```

`wrangler dev` читает `.dev.vars` сам, так что токен для разработки берётся
оттуда же. Вебхук на localhost телеграм слать не умеет — ответы при локальной
отладке приходят только если указать вебхуком адрес боевого воркера.
