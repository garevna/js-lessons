# ![ico-30 study] Приведение типов⟪pryvedenye_typov⟫

Тот факт, что движок позволяет нам использовать данные различного типа в выражениях, приводит к неприятным последствиям: мы никогда не можем быть уверены в типе данных результата. Такая неоднозначность приводит к ошибкам, сбоям в работе приложения.
Одним из наиболее неприятных результатов такой неоднозначности является появление коварного значениия **~NaN~** (~Not a Number~) в наших вычислениях.

~~~demo
> var x = 10, y = '***'
< undefined
> x * y
< NaN
~~~

Учитывая специфическое поведение логических операторов **~&&~** и **~||~**, мы также никогда не можем быть абсолютно уверены в результате вычисления выражений, построенных с их помощью.
Действительно, если операнды выражения, построенного с помощью логических операторов **~&&~** и **~||~**, имеют различный тип данных, то какой тип данных будет у результата?

~~~demo
> var x = 10, y = '***'
< undefined
> x && y
< '***'
> x || y
< 10
> typeof (x && y)
< 'string'
> typeof (x || y)
< 'number'
~~~

## ![ico-25 icon] Явное приведение типов⟪Explicit_type_coercion⟫

••Явное приведение типов данных позволяет нам избежать неоднозначности результата вычисления выражений.••

Самый простой способ явного приведения данных произвольного типа к типу ~string~, ~number~ или ~boolean~ - использование встроенных одноименных функций **~String()~**, **~Number()~**, **~Boolean()~**.

~~~demo
> Number('10')
< 10
> Number('***')
< NaN
> Number(undefined)
< NaN
> String(50)
< '50'
> String(false)
< 'false'
> String(undefined)
< 'undefined'
> Boolean('50')
< true
> Boolean(50)
< true
~~~

Специальное значение **~NaN~** (~Not a Number~) означает, что результат операции не является числом, но при этом результат будет иметь тип **~number~**.

### ![ico-20 icon] Явное приведение к типу number⟪Explicit_type_coercion_to_number⟫

Арифметические операции вычитания, умножения, деления и взятия остатка от деления всегда возвращают результат типа **~number~**, но не факт, что этот результат будет числом.

Аналогично, явное приведение к типу **~number~** с помощью функции-конструктора **~Number()~** всегда вернет результат типа **~number~**, но не факт, что этот результат будет числом.

![ico-20 pin] Обратите внимание, в каких случаях явное приведение к типу **~number~** с помощью функции-конструктора **~Number()~** будет возвращать **~0~**:

~~~demo
> Number(null)
< 0
> Number(false)
< 0
> Number('')
< 0
> Number(' ')
< 0
> Number([])
< 0
> Number([0])
< 0
> Number([''])
< 0
> Number([' '])
< 0
> Number('\n')
< 0
> Number('\t')
< 0
> Number('\r')
< 0
> Number('\v')
< 0
> Number('\f')
< 0
~~~

••Приведение 'пробельных' символов к типу **_number_** всегда возвращает 0.••

^^^[Пробельные символы]

^^К числу 'пробельных' символов относятся пустая строка (""), символ пробела ("   "), а так же спец.символы с кодами:^^

| Symbol    | Code | Description |
| **~\t~**  |   9  | горизонтальная табуляция     |
| **~\n~**  |  10  | перевод строки     |
| **~\v~**  |  11  | вертикальная табуляция     |
| **~\f~**  |  12  | перевод страницы     |
| **~\r~**  |  13  | возврат каретки     |

^^В разных ОС для переноса текста на новую строку используются разные комбинации символов **~\r~** и **~\n~**:^^
^^• **Windows**: Использует пару символов **~\r~** + **~\n~**.^^
^^• **Linux / macOS**: Использует только символ **~\n~**.^^

^^^

Давайте посмотрим, в каких случаях явное приведение к типу **~number~** с помощью функции-конструктора **~Number()~** будет возвращать **~NaN~**:

~~~demo
> Number(undefined)
< NaN
> Number({})
< NaN
> Number(NaN)
< NaN
> Number('5 + 3')
< NaN
> Number('40px')
< NaN
> Number([5, 7])
< NaN
~~~

Функция-конструктор **~Number()~** приводит к типу **~number~** только примитивные значения, т.е. строки, числа, логические значения, **~null~**, **~NaN~**, **~undefined~**.
Движок вычисляет значение выражения, передаваемого функции-конструктору **~Number()~** в круглых скобках. Если результат будет примитивным значением, то это значение будет передано функції-конструктору **~Number()~**.
Если же результат является массивом или объектом, то движок воспользуется **_встроенным механизмом вычисления примитивного значения_** этого объекта.
По умолчанию для получения примитивного значения массива или объекта они приводятся к типу **~string~**, [►►► ^^но это поведение можно изменить^^ ►►►](page/value-of).

~~~demo
> String({})
< '[object Object]'
> Number('[object Object]')
< NaN
> String([5, 4, 8])
< '5,4,8'
> Number('5,4,8')
< NaN
~~~

Итак, функция-конструктор **~Number()~** принимает только примитивные значения, поэтому движок сначала преобразует выражение в круглых скобках функции-конструктора **~Number()~** к примитивному типу данных, а потом уже происходит преобразование этого примитивного типа в тип **~number~**.

| **~x~**     | **~Number(x)~**       |
| ~number~    | **~x~**               |
| ~string~    | Если строка содержит только цифры и разделитель разрядов, то результатом будет число, в противном случае - **~NaN~**.               |
| ~boolean~   | ~true~ → 1<br />~false~ → 0    |
| ~array~     | Массив приводится к строке: ~[a, b, c]~ → ~'a,b,c'~. Если массив пустой, то строка будет пустой. Далее смотри выше приведение строки к числовому типу.               |
| ~object~    | Объект приводится к строке ~'[object Object]'~, поэтому результат приведения типов будет **~NaN~**.               |

![ico-25 hw] Тесты

→→→ Number(57) | NaN, 57, undefined | 57 →→→
→→→ Number(4 * '8') | NaN, 32, 0 | 32 →→→
→→→ Number([8]) | NaN, 8, 0 | 8 →→→
→→→ Number([5] + [8]) | NaN, 13, 8, 5 | 13 →→→
→→→ Number(null - true) | NaN, null, true, 1, -1, 0 | -1 →→→

Как мы убедились, функция-конструктор **~Number()~** не обладает достаточной гибкостью для приведения строк к типу **~number~**.

К счастью, у нас есть более гибкие альтернативы.

#### ![ico-20 icon] parseInt & parseFloat⟪parseInt_&_parseFloat⟫

Для приведения к целому числу или к числу с плавающей запятой (с десятичными знаками) можно использовать встроенные функции ~parseInt~ и ~parseFloat~.
В отличие от конструктора **~Number~**, эти функции парсят строку, даже если в ней есть "левые" символы после числа - эти символы просто будут проигнорированы:

◘◘![ico-25 cap] **7**◘◘

~~~js
Number('3.14abc')      // NaN
parseFloat('3.14abc')  // 3.14
parseInt('3.14abc')    // 3

Number('3.14/5')        // NaN
parseFloat('3.14/5')    // 3.14
~~~

~~~demo
> var sample = '3.14abc'
< undefined
> Number(sample)
< NaN
> parseFloat(sample)
< 3.14
> parseInt(sample)
< 3
> Number('3.14 / 5')
< NaN
> parseFloat('3.14 / 5')
< 3.14
> Number('3.14 * 5')
< NaN
> parseFloat('3.14 * 5')
< 3.14
~~~

Однако если строка начинается с символов, которые не могут быть приведены к числу, эти функции вернут **~NaN~**.

При приведении строки к булевому типу действует простое правило:

если длина строки равна 0, то возвращается ~false~, в противном случае - ~true~

### ![ico-20 icon] Явное приведение к ~string~⟪Explicit_coercion_to_~string~⟫

~~~demo
> var str = String(5 + 8 + false)
< undefined
> str
< "13"
> var object = {}
< undefined
> String(object)
< "[object Object]"
> var array = [5, true, 'hello', 11]
< undefined
> String(array)
< "5,true,hello,11"
~~~

При приведении числа к типу ~string~ можно использовать метод **~toString()~**, который принимает один аргумент - десятичное число 2, 8 или 16 (система исчисления).
^^Десятичная система исчисления подразумевается по умолчанию, поэтому аргумент при этом можно опустить.^^
^^Для того, чтобы получить строчное значение числа в двоичной системе исчисления, нужно передать методу **~toString()~** аргумент 2, в восьмеричной - 8, в шестнадцатеричной - 16.^^

~~~demo
> Number(2).toString(2)
< "10"
> Number(58).toString(2)
< "111010"
> Number(8).toString(8)
< "10"
> Number(58).toString(8)
< "72"
> Number(16).toString(16)
< "10"
> Number(58).toString(16)
< "3a"
~~~
