У розробці часто трапляються одні й ті самі проблеми, і для багатьох таких проблем уже існує готовий шаблон вирішення, оскільки багатьом до вас уже доводилося стикатися з аналогічною проблемою

Для створення патерну проблему потрібно формалізувати, тобто описати формальною мовою суть проблеми

## ![ico-25 icon] Поведінкові патерни⟪Behavioural_patterns⟫

До поведінкових патернів належить уже знайомий нам **ітератор**

Яку проблему загального характеру вирішує цей патерн?

По-перше, він забезпечує механізм послідовного доступу до елементів структури даних
По-друге, ітератор працює з «чорною скринькою» — зовні не видно, що саме він ітерує, доти, доки не будуть виконані всі ітерації
По-третє, ітератор опосередковує доступ до структури даних, задаючи суворий порядок операцій з її елементами

Нарешті, структура даних може й не бути структурою даних — це може бути ланцюжок певних операцій, викликів функцій тощо

## ![ico-25 icon] Делегування⟪Delegation⟫

У прототипній моделі успадкування, по суті, відсутній сам механізм успадкування, оскільки він замінюється механізмом **делегування**

Дійсно, що таке прототип? — це об’єкт, відмінний від того об’єкта, прототипом якого він є

Давайте створимо два об’єкти: **proto** та **media**

і зробимо об’єкт **proto** прототипом об’єкта **media**

◘◘![ico-25 cap] ** 1**◘◘

~~~js
const proto = {
  showPicture () {
    document.body
      .appendChild(document.createElement('img'))
      .src = 'https://cdn.pixabay.com/photo/2014/04/04/10/51/darling-harbour-313216_960_720.jpg'
  }
}

const media = {
  sayHello () {
    document.body
      .appendChild(document.createElement('h3'))
      .innerText = 'Hello!'
  }
}

Object.setPrototypeOf(media, proto)
~~~

Якщо тепер ми викличемо метод **_showPicture_** об’єкта **media**:

~~~js
media.showPicture()
~~~

то, по суті, ми делегуємо об’єкту **proto** те, чого не може зробити об’єкт **media**,
оскільки у нього немає такого методу

Тому весь ланцюжок прототипів є, по суті, ланцюжком делегування, а не успадкування

Якщо розглядати делегування як шаблон проектування в ООП, то можна навести й інші приклади

◘◘![ico-25 cap] ** 2**◘◘

~~~js
const media = {
  image: true,
  method () {
    document.body
      .appendChild(document.createElement('img'))
      .src = 'https://garevna.github.io/js-samples/images/js-ico.png'
  }
}

const speaker = {
  text: true,
  method () {
    document.body
      .appendChild(document.createElement('h3'))
      .innerText = 'Hello'
  }
}

const dispetcher = {
  workers: [speaker, media],
  getSignal (signal) {
    const worker = this.workers.find(worker => worker[signal])
    worker && worker.method()
  }
}
~~~
