# ![ico-30 study] Context⟪Context⟫

Поговоримо про контекст виклику звичайної та стрілкової функції

Контекст виклику звичайної функції за замовчуванням встановлюється під час її оголошення, але може бути змінений під час виклику за допомогою методів ~call~ або ~apply~

Однак для оголошення звичайної функції ми можемо використовувати ~function declaration~ або ~function expression~
Другий варіант — це присвоєння, в результаті якого контекст виклику за замовчуванням визначається лівою частиною:

**Приклад 1**

~~~js
user.showContext = function () {
  console.log(this)
}
~~~

Тут ми визначили контекст у лівій частині оператора присвоєння, тобто контекст виклику — ~user~

Контекст стрілкової функції встановлюється в момент її оголошення, і присвоєння не змінює її контекст, оскільки він уже чітко визначений — це контекст, у якому вона була створена (права частина оператора присвоєння):

**Приклад 2**
~~~js
user.sayHello = () => console.log(this)
~~~
тут уже ~user.sayHello~ має глобальний контекст 😉

-------------------

Коли ми оголошуємо метод за допомогою скороченого синтаксису, тобто ось так:
~~~js
const boy = {
  name: 'Robert',
  showContext () {
    console.log(this)
  }
}
~~~
то відбувається присвоєння, коли в правій частині — звичайна функція, а в лівій — ~boy.showContext~
таким чином, має місце **приклад 1**

Якщо ж ми використовуємо стрілкову функцію:
~~~js
const boy = {
  name: 'Robert',
  showContext: () => console.log(this)
}
~~~
то  маємо **приклад 2**

-------------------

Якщо ви засвоїли попереднє, заглибимося далі 😂

**sample 1**

у цьому прикладі метод ~user~ об’єкта ~create~ створюється за допомогою скороченого синтаксису оголошення методів (**приклад 1**)
у результаті контекст виклику цього методу — ~user~
метод ~create~ повертає об’єкт, у якому буде метод ~showContext~
контекст виклику методу ~user~ — із **прикладу 2**, тобто ~create~, оскільки саме в цьому контексті працює метод ~showContext~, що його створює
Таким чином, колбек таймера — це стрілкова функція, яка «народжується» у контексті ~user~

~~~js
const user = {
  name: 'Henry',
  create () {
    return {
      name: 'Jeck',
      showContext: () => setTimeout(() => console.log(this))
    }
  }
}

user.create().showContext()  // { name: 'Henry', create: ƒ }
~~~

**sample 2**

А в цьому прикладі метод ~showContext~ оголошено за допомогою скороченого синтаксису оголошення методів (**приклад 1**)
Отже, контекст виклику — це контекст об’єкта, який повертає метод ~create~ (об’єкт з іменем _Jeck_)
Колбек таймера отримує цей контекст
~~~js
const user = {
  name: 'Henry',
  create () {
    return {
      name: 'Jeck',
      showContext () { setTimeout(() => console.log(this)) }
    }
  }
}

user.create().showContext()  // { name: 'Jeck', showContext: ƒ }
~~~

Внесіть «невелику» зміну в код першого прикладу, яка змінює контекст виклику методу ~create~ — і ви вже в глобальному об’єкті
~~~js
const user = {
  name: 'Henry',
  create: () => {
    return {
      name: 'Jeck',
      showContext: () => setTimeout(() => console.log(this))
    }
  }
}
~~~
Однак у **sample 2** колбек таймера бачитиме контекст, як і раніше
~~~js
const user = {
  name: 'Henry',
  create: () => {
    return {
      name: 'Jeck',
      showContext () { setTimeout(() => console.log(this)) }
    }
  }
}
~~~

ну, і так далі

експериментуйте, це корисно для глибокого розуміння контексту виклику 😉
