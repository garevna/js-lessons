## ![ico-25 icon] Чиста функція⟪pure_function⟫

•••• none
![ico-20 memo] **Чиста функція** — це функція, яка:
![ico-20 pin] при однакових значеннях аргументів повертає один і той самий результат (передбачувана поведінка)
![ico-20 pin] не впливає на зовнішнє оточення, тобто не змінює значення зовнішніх змінних (не створює побічних ефектів)
![ico-20 pin] не залежить від стану оточення, оскільки не використовує зовнішні змінні у своїх обчисленнях
••••

### ![ico-20 icon] Посилальна прозорість⟪referential_transparency⟫

••![ico-20 pin] **Посилальна прозорість** (**_referential transparency_**) — це можливість замінити виклик функції із заданим набором аргументів результатом її виклику.••

~~~js
const func = (x, y, z) => x + y - z
~~~

^^Виклик функції **~func(3, 4, 2)~** завжди повертає 5, тому можна замінити **~func(3, 4, 2)~** значенням 5.^^

^^А ось така функція не матиме властивості **~referential transparency~**, оскільки результат її роботи буде псевдовипадковим числом:^^


~~~js
const func = (x, y, z) => x + y - z * Math.random()
~~~

^^У наступному прикладі функція **~counter~** також не буде посилально-прозорою, оскільки кожен виклик цієї функції повертатиме новий результат:^^

~~~js
const makeCounter = () => {
  let counter = 0
  return () => counter++
}

const counter = makeCounter()
~~~

••••
Що забезпечує посилальна прозорість? — оптимізацію.
Движок може «запам’ятати» вже обчислене значення функції із заданим набором аргументів, і при повторному виклику функції з тим самим набором аргументів повернути вже обчислене раніше значення.
••••

### ![ico-20 icon] Імутабельність⟪Immutability⟫

••••
![ico-20 pin] **Імутабельність** (**_immutability_**) — це стійкість до змін.
Імутабельні дані — це дані, які не змінюються з плином часу.
••••

^^У наступному прикладі змінна **~sum~** тричі змінює своє значення під час виконання циклу:^^

~~~js
const numbers = [10, 5, 7]
let sum = 0

for (const number of array) {
  sum += number
}
~~~

^^А якщо скористатися функцією **~summation~**:^^

~~~js
const summation = array => {
  return (function recurse (index = 0, sum = 0) {
    sum += array[index++]
    return index < array.length ? recurse (index, sum) : sum
  })()
}
~~~

^^то після виклику^^

~~~js
const numbers = [10, 5, 7]

summation(numbers)  // 22
~~~

^^масив **~numbers~** і змінна **~sum~** не зміняться, тобто функція **~summation~** не спричиняє зовнішніх ефектів.^^

^^А ось такий варіант функції **~summation~**:^^

~~~js
const numbers = [10, 5, 7]

const summation = (sum = 0) => {
  while (numbers.length > 0) {
    sum += numbers.shift()
  }
  return sum
}
~~~

^^спричиняє «зовнішні ефекти», оскільки в результаті виклику функції:^^

~~~js
summation()
~~~

^^змінюються значення зовнішніх змінних **~numbers~** та **~sum~**.^^

◘◘![ico-25 cap] ** 1**◘◘

~~~js
const numbers = [10, 5, 7]

const summation = (sum = 0) => {
  for (const num of numbers) {
    sum += numbers.shift()
    numbers.push(sum)
  }
  console.log(`[${numbers.toString()}]:`, sum)
}

summation()
summation()
summation()
~~~

~~~console
[10,15,22]: 22
[10,25,47]: 47
[10,35,82]: 82
~~~

### ![ico-20 icon] Ідемпотентність⟪Idempotence⟫

•••• none
![ico-20 pin] Ідемпотентна функція — це функція, повторне або багаторазове застосування якої дає той самий результат, що й перше. Тобто якщо ми застосуємо одну й ту саму функцію двічі або тричі до одного й того самого набору аргументів, то результат буде таким самим, як і при першому виклику цієї функції з цим набором аргументів.
Чи не змінить повторний виклик ідемпотентної функції стан системи? — не обов’язково. Якби це було так, то ідемпотентна функція була б за визначенням чистою. Ідемпотентність є необхідною, але не достатньою умовою чистоти функції. Ідемпотентна функція може змінювати зовнішні дані. Дійсно, у нас є типи даних-посилань, і якщо функція отримує посилання як аргумент, то незмінність самого посилання не є гарантією того, що дані (масив або об’єкт), на які вказує це посилання, не змінюються. Тобто ідемпотентна функція отримуватиме той самий аргумент (посилання), але це не означає, що вона отримує той самий набір даних за цим посиланням.
••••

~~~js
function setAdmin (user) {
  user.role = 'admin'
  return user
}
~~~

Очевидно, що ідемпотентність функцій дуже тісно пов’язана з імутабельністю даних. Якщо функція оперує мутабельними даними, то її результат є непередбачуваним, тобто вона не буде ідемпотентною.
Наприклад, функція **~summation~** із прикладу 1 не є **ідемпотентною**, тому що кожен виклик функції **~summation~** змінює вихідний масив, змінюючи, таким чином, результат наступного виклику функції.

Наведемо найпростіший приклад ідемпотентної функції **~five~**: вона завжди повертає 5, тому застосування цієї функції до результату попереднього виклику нічого не змінює, про що свідчить те, що ми бачимо в консолі:

~~~js
function five () {
  console.log(5)
  return 5
}

five(five(five(five())))
~~~

~~~console
5
5
5
5
<• 5
~~~

Отже, результат виклику ідемпотентної функції є передбачуваним, вона оперує імутабельними даними. Хороший кандидат на звання «чистої» функції, якщо вона не спричиняє побічних ефектів, тобто не змінює стан системи. Однак це не завжди так. Функція може бути ідемпотентною, але при цьому спричиняти побічні ефекти, тобто не бути «чистою» функцією. Наприклад:

◘◘![ico-25 cap] **2**◘◘

~~~js
function initArray (array) {
  if (!Array.isArray(array) {
    return false
  }
  array.length = 0
  array.push(1, 2, 3, 4, 5)
  return true
}
~~~

••Мутації стану системи роблять роботу додатка нестабільною, ускладнюють процес налагодження та тестування.••

## ![ico-25 icon] Функція вищого порядку⟪Higher-order_function⟫

••**_Функція вищого порядку_** — це функція, яка приймає як аргументи інші функції або повертає іншу функцію як результат.••

••••
Оскільки функції в JS є об’єктами, працювати з ними можна абсолютно так само, як з будь-яким об’єктом:
![ico-20 pin] об’єднувати в структури (масиви, об’єкти)
![ico-20 pin] передавати як аргумент
![ico-20 pin] повертати як результат (що, власне, і робить конструктор **_Function_**)
Одним словом, усе, що ми можемо робити з об’єктами, можна робити з функціями, оскільки функції — це всього лише об’єкти класу **_Function_**
••••

### ![ico-20 icon] Функція-аргумент⟪Function_as_an_argument⟫

◘◘![ico-25 cap] ** 3**◘◘

~~~js
function frog () {
  console.log('frog')
}
function elefant () {
  console.log('elefant')
}

function animal (func) {
  func()
}
~~~

У цьому прикладі функція **~animal~** отримує як аргумент посилання на функцію, яку й викликає. Ми можемо передавати функції **~animal~** різні функції.



Викличемо функцію **~animal~**:

~~~js
animal(frog)
animal(elefant)
~~~

і в консолі ми побачимо:

~~~console
frog
elefant
~~~

Однак якщо аргумент функції **~animal~** виявиться не функцією, то при спробі його виклику (у круглих дужках) буде згенеровано виняток (**~TypeError~**)

~~~console
<p class="error-message">Uncaught TypeError&colon; func is not a function</p>
~~~

Щоб уникнути цього, трохи змінимо код функції **~animal~**, додавши перевірку типу аргументу:

~~~js
function animal (func) {
  typeof func === 'function' ? func() : null
}
~~~

Створимо елемент ~div~ і додамо його в ~document.body~

Встановимо властивість _~id~_ цього елемента рівною «_sample_»

Змінимо код функцій **~frog()~** та **~elefant()~**:

~~~js
function frog () {
  return 'frog'
}
function elefant () {
  return 'elefant'
}
~~~

Тепер оголосимо функцію **~newFunc()~**, яка створюватиме новий елемент ~ p~, вставлятиме його в контейнер з ідентифікатором _elemId_ та встановлюватиме його вміст (_~innerHTML~_) за допомогою функції, переданої як аргумент:

~~~js
function newFunc (func, elemId) {
  const elem = document.getElementById(elemId)

  if (!elem || !elem.nodeType || elem.nodeType !== 1) return

  function makeElem () {
    const el = document.createElement('p')
    elem.appendChild(el)
    el.innerHTML = func()
    console.log(el)
  }

  typeof func === 'function' && makeElem(func, elem)
}
~~~

Викличемо функцію **~newFunc~**, передавши їй функцію **~frog~** як перший аргумент, а другим аргументом передамо їй ~id~ створеного нами елемента («_sample_»):

~~~js
newFunc(frog, 'sample')
~~~

У результаті на сторінці з’явиться новий елемент із текстом, який повертає функція **~frog()~**

Тепер викличемо функцію **~newFunc()~**, передавши їй функцію **~elefant()~**:

~~~js
newFunc(elefant, 'sample')
~~~

У результаті на сторінці з’явиться новий елемент із текстом, який повертає функція **~elefant()~**.

### ![ico-20 icon] Функція як значення, що повертається⟪A_function_as_a_return_value⟫

Тепер оголосимо функцію **~createFunction()~**, яка повертатиме функцію:

◘◘![ico-25 cap] ** 4**◘◘

~~~js
function createFunction (param) {
  return function () {
    console.log('function ', param)
  }
}
~~~

і створимо за її допомогою дві нові функції: **~firstFunc()~** та **~secondFunc()~**:

~~~js
var firstFunc = createFunction('First')
var secondFunc = createFunction('Second')
~~~

Викличемо кожну з цих функцій:

~~~js
firstFunc()
secondFunc()
~~~

В консолі ми побачимо:

~~~console
function  First
function  Second
~~~

### ![ico-20 icon] Ланцюгові обчислення⟪Chain_computations⟫

Наступний приклад ілюструє можливість створення ланцюгових обчислень за допомогою функції вищого порядку:

◘◘![ico-25 cap] **5**◘◘

~~~js
function first (a, b, c) {
  if (!a || typeof a !== 'number') {
      return first
  }
  if (!b || typeof b !== 'number') {
    return function second (b, c) {
      if (!b || typeof b !== 'number') {
        return second
      }
      if (!c || typeof c !== 'number') {
        return function third (c) {
          if (!c || typeof c !== 'number') {
            return third
          }
          return a + b + c
        }
      } else {
        return a + b + c
      }
    }
  } else {
    if (!c || typeof c !== 'number') {
      return function third (c) {
        if (!c) return third
        return a + b + c
      }
    } else {
      return a + b + c
    }
  }
}

console.log('first(5, 10, 20):', first(5, 10, 20))
console.log('first(5)(10)(20):', first(5)(10)(20))
~~~

~~~console
first(5, 10, 20): 35
first(5)(10)(20): 35
~~~

Функція **~first()~** очікує три числові аргументи. Якщо її викликано без аргументів або аргументи не є числами, вона повертає саму себе.
У разі, якщо їй передано лише один аргумент, вона повертає функцію **~second()~**, яка очікує вже два числові аргументи, оскільки перший уже є в її області видимості (scope).
Якщо під час виклику функції **~second()~** не передано жодного аргументу або ці аргументи не є числами, то вона повертає саму себе.
Якщо під час виклику функції **~second()~** їй передано лише один аргумент, то вона повертає функцію **~third()~**, яка очікує вже лише один числовий аргумент, оскільки два перших уже є в її області видимості (scope).
Якщо під час виклику функції **~third()~** їй не передано числовий аргумент, вона поверне саму себе.
У разі передачі функції **~third()~** числового аргументу вона поверне суму всіх трьох аргументів.

~~~js
const second = first(5)
const third = second(10)
console.log('third(20):', third(20))
~~~

~~~console
third(20): 35
~~~

~~~js
console.log('first("a", "b", "c")')
console.dir(first('a', 'b', 'c'))
~~~

~~~console
first("a", "b", "c")

  ► prototype: {}
    arguments: null
    caller: null

~~~

~~~js
console.log('first(5, 10, "*"):')
console.dir(first(5, 10, '*'))
~~~

~~~js
first('*')(undefined)(5)(NaN)(7)(false)(null)(3)
~~~
