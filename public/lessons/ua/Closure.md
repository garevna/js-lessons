# ![ico-30 study] Замикання

[Замикання](external/w3-closures) — це ефект, за допомогою якого можна «приховати» змінні в контексті батьківської функції, що повертає функцію.

[Замкнення](external/mdn-closures) — це комбінація: функція + лексичне середовище, в якому ця функція була оголошена.

Якщо функція повертає функцію, то лексичне середовище батьківської функції потрапляє в ланцюжок областей видимості дочірньої функції.

Тобто всі аргументи, отримані батьківською функцією під час виклику, а також усі змінні та функції, оголошені в ній, будуть доступні дочірній функції (вона їх «бачить»)

^^Однак більше ніде вони доступні не будуть, оскільки посилання на них доступні лише дочірній функції.^^

Отже, ефект замикання виникає лише в тому випадку, якщо функція повертає функцію.

◘◘![ico-25 cap] ** 1**◘◘

~~~js
function parent (arg) {
  var frog = 'I\'m frog'
  return function () {
    console.log(arg, frog)
  }
}

var child = parent('Hello!')
~~~

Викличемо дочірню функцію:

~~~js
child()  // Hello!  I'm frog
~~~

◘◘![ico-25 cap] ** 2**◘◘

~~~js
var parent = message => () => console.log(message)

var hello = parent('Hello!')
var welcome = parent('Welcome!')

hello()    // Hello!
welcome()  // Welcome!
~~~

Альтернативою замиканню є інший механізм — каррінг:

◘◘![ico-25 cap] ** 3**◘◘

~~~js
var parent = message => console.log(message)

var hello = parent.bind(null, 'Hello!')
var welcome = parent.bind (null, 'Welcome!')

hello()    // Hello!
welcome()  // Welcome!
~~~

◘◘![ico-25 cap] ** 4**◘◘

~~~js
function parent (omega) {
  var alpha = 0
  return () => omega > alpha
    ? omega-- - alpha++
    : null
}

var child = parent(20)
~~~

Тепер кожен черговий виклик функції **child** повертатиме нове число, менше за попереднє на 2
і так доти, доки повернене значення буде більшим за 0

~~~js
child() // 20
child() // 18
...
~~~

◘◘![ico-25 cap] ** 5**◘◘

~~~js
function first (firstArg) {
  function second (secondArg) {
    return firstArg.toString().split('').join(secondArg)
  }
  return function () {
    return second('*')
  }
}

first('Happy New Year!')()
~~~

Результат буде: ••«H*a*p*p*y* *N*e*w* *Y*e*a*r*!»••

## ![ico-25 icon] IIFE

**_Immediately Invoked Function Expression_**

Функціональний вираз [**IIFE**](external/mdn-iife), тобто виклик оголошуваної анонімної функції «на місці»
(у місці її оголошення)

У цьому прикладі анонімна функція «загорнута» в круглі дужки:

◘◘![ico-25 cap] ** 6**◘◘

~~~js
(function (userName) {
  return {
    name: userName,
    visit: new Date().toLocaleDateString(),
    id: new Date().getTime()
  }
})
~~~

Коли інтерпретатор доходить до рядка, в якому знаходиться цей код, він обчислює вираз у круглих дужках,
і значенням цього виразу буде **посилання** на функцію, оголошення якої знаходиться в дужках.

~~~console
ƒ (userName) {
  return {
    name: userName,
    visit: new Date().toLocaleDateString(),
    id: new Date().getTime()
  }
}
~~~

Якщо після цього функціонального виразу поставити круглі дужки, то відбудеться негайний виклик функції в місці її оголошення:

~~~js
(function (userName) {
  return {
    name: userName,
    visit: new Date().toLocaleDateString(),
    id: new Date().getTime()
    }
})()
~~~

Оскільки оголошена всередині круглих дужок функція повертає об’єкт, то результат буде таким:

~~~console
▼ { name: undefined, visit: "04.07.2019", id: 1562225761228 }
    id: 1562225761228
    name: undefined
    visit: "04.07.2019"
  ► __proto__: Object
~~~

Оскільки отримане посилання на функцію ми не зберігаємо, то збирач сміття під час чергового проходу видалить об’єкт функції з пам’яті.
Тому всередині дужок оголошується анонімна функція, оскільки її ім’я ніколи не буде використано.

Виклик функції без аргументу призвів до того, що властивість name об’єкта отримала значення undefined

Передамо функції аргумент, причому ім’я отримаємо через модальне вікно prompt:

~~~js
var user = (function (userName) {
  return {
    name: userName,
    visit: new Date().toLocaleDateString(),
    id: new Date().getTime()
  }
})(prompt('Enter your name:'))
~~~

У модальному вікні введемо ім’я **_Семен_**

У результаті змінна user стане об’єктом:

~~~console
▼ { name: "Семен", visit: "04.07.2019", id: 1562226083644 }
    id: 1562226083644
    name: "Семен"
    visit: "04.07.2019"
  ► __proto__: Object
~~~

Анонімна функція була викликана лише один раз, після чого вона видаляється з пам’яті (оскільки посилання на неї не зберігається).

______________________

У цьому прикладі анонімна функція отримує аргумент «Hello», оголошує змінну **_message_** у своїй функціональній області видимості,
у якій зберігає отримане значення аргументу, і повертає анонімну функцію.

При цьому її контекст демонтується (видаляється зі стека), і логічно припустити, що змінна **_message_** також буде видалена з пам’яті,

![ico-20 yes] але!

Збірник сміття не може видалити змінну  **_message_**  з пам’яті, оскільки анонімна функція, що повертається, використовує у своєму контексті посилання на неї.

А поки є хоча б одне активне посилання на змінну, збирач сміття не може очистити пам’ять, виділену під цю змінну.

Цей ефект називається «замкнення».

Після обчислення значення функціонального виразу у змінній **_func_** буде посилання на анонімну функцію,
у контексті якої буде «замкнена» змінна **_message_**.

Тепер посилання на змінну **_message_** існує лише в контексті функції, що повертається.

◘◘![ico-25 cap] ** 7**◘◘

~~~js
var sayHello = (function (message) {
  return function (name) {
    console.log(`${ message }, ${ name }`)
  }
})('Hello')

sayHello('Дима')
sayHello ('Николай')
~~~

Ефект замикання часто використовується для захисту змінних, але слід пам’ятати, що це лише побічний ефект, а не прийом, і цей ефект може призводити до витоків пам’яті.

## ![ico-25 icon] Паттерн «Модуль»

Поєднання IIFE з ефектом замикання дає нам один із патернів проектування під назвою «Модуль», який, на жаль, активно використовується в розробці, а також під час компіляції додатків.

Будь-який додаток (application) складається з модулів, кожен із яких має власну ізольовану область видимості.
Усі змінні та функції, оголошені в модулі, доступні лише в межах цього модуля.

Але для того, щоб «сховати» змінні та функції всередині модуля, логічніше використовувати прийом каррірування, а не побічний ефект роботи збирача сміття.
Раджу уважно ознайомитися з прийомом каррірування, який запозичений із функціональних мов програмування і є більш коректним способом не тільки «ховати» змінні всередині функції (модуля), але й будувати красиві ланцюгові обчислення.

## ![ico-25 warn] Function

![ico-20 err] Функції, створені конструктором **Function**, не створюють замикання

◘◘![ico-25 cap] ** 8**◘◘

~~~js
var __var__ = 'Global Scope'

function functionConstructor() {
  var __var__ = 'Function Scope'
  return new Function('console.warn(__var__)')
}

function functionDeclaration() {
  var __var__ = 'Closured Scope'
  return function () {
    console.info(__var__)
  }
}

functionConstructor()()   // Global Scope
functionDeclaration()()   // Closured Scope
~~~

## ![ico-25 warn] Memory Leaks

![ico-20 warn] Замикання може призводити до витоків пам’яті.

Наступний код призведе до зупинки програми через переповнення пам’яті:

◘◘![ico-25 cap] ** 9**◘◘

~~~js
var globalFunc

function closure () {
  var data = new Array(1000000)
  var func = globalFunc

  function innerFunc() {
    if (func) return data
  }

  return function () {}
}

setInterval(() => globalFunc = closure(), 5)
~~~

Чому в цьому фрагменті коду виникають витоки пам’яті?

Щоразу, коли спрацьовує таймер, викликається ~closure~ і відбувається перевизначення значення ~globalFunc~
У кожному новому варіанті ~globalFunc~ у замикання потрапляють змінні ~data~, ~func~ та ~innerFunc~
При цьому посилання на попереднє значення ~globalFunc~ потрапляє в локальну змінну ~func~,
яка потрапила в замикання нового значення ~globalFunc~,
тим самим разом із попереднім значенням ~globalFunc~ у замикання потрапляють усі змінні,
які були в замиканні ~globalFunc~, тобто, зокрема, ~innerFunc~
Змінна ~data~ займатиме чималий обсяг пам’яті
Посилання на ~data~ потрапляє в замикання ~innerFunc~
~innerFunc~ потрапляє в замикання кожної нової версії ~globalFunc~

Виходить глибока вкладеність змінних у замиканні, і ~data~ дублюватиметься доти,
доки це не призведе до переповнення пам’яті (дуже швидко, оскільки інтервал таймера — 5 мілісекунд)
