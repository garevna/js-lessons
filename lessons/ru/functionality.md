## ![ico-25 icon] Чистая функция⟪pure_function⟫

•••• none
![ico-20 memo] **Чистая функция** - это функция, которая:
![ico-20 pin] при одних и тех же значениях аргументов возвращает один и тот же результат (предсказуемое поведение)
![ico-20 pin] не влияет на внешнее окружение, т.е. не изменяет значения внешних переменных (не создает побочных эффектов)
![ico-20 pin] не зависит от состояния окружения, потому что не использует внешние переменные в своих вычислениях
••••

### ![ico-20 icon] Ссылочная прозрачность⟪referential_transparency⟫

••![ico-20 pin] **Ссылочная прозрачность** (**_referential transparency_**) - это возможность заменить вызов функции с заданным набором аргументов результатом ее вызова.••

~~~js
const func = (x, y, z) => x + y - z
~~~

^^Вызов функции **~func(3, 4, 2)~** всегда возвращает 5, поэтому можно заменить **~func(3, 4, 2)~** значением 5.^^

^^А вот такая функция не будет обладать свойством **~referential transparency~**, поскольку результат ее работы будет псевдо-случайным числом:^^


~~~js
const func = (x, y, z) => x + y - z * Math.random()
~~~

^^В следующем примере функция **~counter~** также не будет ссылочно-прозрачной, поскольку каждый вызов этой функции будет возвращать новый результат:^^

~~~js
const makeCounter = () => {
  let counter = 0
  return () => counter++
}

const counter = makeCounter()
~~~

••••
Ссылочная прозрачность обеспечивает оптимизацию.
Движок может 'запомнить' уже вычисленное значение функции с заданным набором аргументов, и при повторном вызове функции с тем же набором аргументов вернуть уже вычисленное ранее значение.
••••

### ![ico-20 icon] Иммутабельность⟪Immutability⟫

••••
![ico-20 pin] **Иммутабельность** (**_immutability_**) - это устойчивость к изменениям.
Иммутабельные данные - это данные, которые не меняются с течением времени.
••••

^^В следующем примере переменная **~sum~** трижды меняют свое значение в процессе выполнения цикла:^^

~~~js
const numbers = [10, 5, 7]
let sum = 0

for (const number of array) {
  sum += number
}
~~~

^^А если использовать функцию **~summation~**:^^

~~~js
const summation = array => {
  return (function recurse (index = 0, sum = 0) {
    sum += array[index++]
    return index < array.length ? recurse (index, sum) : sum
  })()
}
~~~

^^то после вызова^^

~~~js
const numbers = [10, 5, 7]

summation(numbers)  // 22
~~~

^^массив **~numbers~** и переменная **~sum~** не изменятся, т.е. функция **~summation~** не производит внешних эффектов.^^

^^А такой вариант функции **~summation~**:^^

~~~js
const numbers = [10, 5, 7]

const summation = (sum = 0) => {
  while (numbers.length > 0) {
    sum += numbers.shift()
  }
  return sum
}
~~~

^^производит 'внешние эффекты', поскольку в результате вызова функции:^^

~~~js
summation()
~~~

^^изменяются значения внешних переменных **~numbers~** и **~sum~**.^^

◘◘![ico-25 cap] ** 1**◘◘

~~~js
const numbers = [10, 5, 7]

const summation = (sum = 0) => {
  for (const num of numbers) {
    sum += numbers.shift()
    numbers.push(sum)
  }
  console.log(`[${numbers.toString()}]:`, sum)
}

summation()
summation()
summation()
~~~

~~~console
[10,15,22]: 22
[10,25,47]: 47
[10,35,82]: 82
~~~

### ![ico-20 icon] Идемпотентность⟪Idempotence⟫

•••• none
![ico-20 pin] Идемпотентная функция — это функция, повторное или многократное применение которой дает тот же результат, что и первое. Т.е. если мы применим одну и ту же функцию дважды или трижды к одному и тому же набору аргументов, то результат будет тот же, что и при первом вызове этой функции с этим набором аргументов.
Повторный вызов идемпотентной функции не изменит состояние системы? - не факт. Если бы это было так, то идемпотентная функция была бы по определению чистой. Идемпотентность является необходимым, но не достаточным условием чистоты функции. Идемпотентная функция может мутировать внешние данные. Действительно, у нас есть ссылочные типы данных, и если функция получает ссылку в качестве аргумента, то неизменность самой ссылки не является гарантией того, что данные (массив или объект), адресуемые этой ссылкой, не мутируют. Т.е. идемпотентная функция будет получать тот же аргумент (ссылку), но это не означает, что она получает тот же набор данных по этой ссылке.
••••

~~~js
function setAdmin (user) {
  user.role = 'admin'
  return user
}
~~~

Очевидно, что идемпотентность функций очень тесно связана с иммутабельностью данных. Если функция оперирует с мутабельными данными, то ее результат непредсказуем, т.е. она не будет идемпотентной.
 Например, функция **~summation~** из примера 1 не является **идемпотентной**, потому что каждый вызов функции **~summation~** мутирует исходный массив, меняя, таким образом, результат следующего вызова функции.

Приведем простейший пример идемпотентной функции **~five~**: она всегда возвращает 5, поэтому применение этой функции к результату предыдущего вызова ничего не меняет, в чем нас убеждает то, что мы видим в консоли:

~~~js
function five () {
  console.log(5)
  return 5
}

five(five(five(five())))
~~~

~~~console
5
5
5
5
<• 5
~~~

Итак, результат вызова идемпотентной функции предсказуем, она оперирует иммутабельными данными. Хороший кандидат на звание 'чистой' функции, если она не производит побочных эффектов, т.е. не меняет состояние системы. Однако это не всегда так. Функция может быть идемпотентной, но при этом производить побочные эффекты, т.е. не быть "чистой" функцией. Например:

◘◘![ico-25 cap] **2**◘◘

~~~js
function initArray (array) {
  if (!Array.isArray(array) {
    return false
  }
  array.length = 0
  array.push(1, 2, 3, 4, 5)
  return true
}
~~~

••Мутации состояния системы делают работу приложения неустойчивой, затрудняет процесс отладки и тестирования.••

## ![ico-25 icon] Функция высшего порядка⟪Higher-order_function⟫

••**_Функция высшего порядка_** — это функция, принимающая в качестве аргументов другие функции или возвращающая другую функцию в качестве результата.••

••••
Поскольку функции в JS являются объектами, действовать с ними можно абсолютно так же, как с любым объектом:
![ico-20 pin] собирать в структуры (массивы, объекты)
![ico-20 pin] передавать в качестве аргумента
![ico-20 pin] возвращать в качестве результата (что, собственно, и делает конструктор **_Function_**)
Одним словом, все, что мы можем делать с объектами, можно делать с функциями, поскольку функции - это всего лишь объекты класса **_Function_**
••••

### ![ico-20 icon] Функция-аргумент⟪Function_as_an_argument⟫

◘◘![ico-25 cap] ** 3**◘◘

~~~js
function frog () {
  console.log('frog')
}
function elefant () {
  console.log('elefant')
}

function animal (func) {
  func()
}
~~~

В этом примере функция **~animal~** получает в качестве аргумента ссылку на функцию, которую и вызывает. Мы можем передавать функции **~animal~** различные функции.



Вызовем функцию **~animal~**:

~~~js
animal(frog)
animal(elefant)
~~~

и в консоли мы увидим:

~~~console
frog
elefant
~~~

Однако если аргумент функции **~animal~** окажется не функцией, то при попытке его вызова (с круглыми скобками) будет сгенерировано исключение (**~TypeError~**)

~~~console
<p class="error-message">Uncaught TypeError&colon; func is not a function</p>
~~~

Во избежание этого немного изменим код функции **~animal~**, добавив проверку типа аргумента:

~~~js
function animal (func) {
  typeof func === 'function' ? func() : null
}
~~~

Создадим элемент ~div~ и добавим его в ~document.body~

Установим свойство _~id~_  этого элемента  равным "_sample_"

Изменим код функций **~frog()~** и **~elefant()~**:

~~~js
function frog () {
  return 'frog'
}
function elefant () {
  return 'elefant'
}
~~~

Теперь объявим функцию **~newFunc()~**, которая будет создавать новый элемент ~ p~, вставлять его в контейнер с идентификатором _elemId_ и устанавливать его содержимое (_~innerHTML~_) с помощью функции, переданной аргументом:

~~~js
function newFunc (func, elemId) {
  const elem = document.getElementById(elemId)

  if (!elem || !elem.nodeType || elem.nodeType !== 1) return

  function makeElem () {
    const el = document.createElement('p')
    elem.appendChild(el)
    el.innerHTML = func()
    console.log(el)
  }

  typeof func === 'function' && makeElem(func, elem)
}
~~~

Вызовем  функцию **~newFunc~**, передав ей функцию **~frog~** в качестве первого аргумента, а вторым аргументом передадим ей  ~id~ созданного нами элемента ("_sample_"):

~~~js
newFunc(frog, 'sample')
~~~

В результате на странице появится новый элемент с текстом, который возвращает функция **~frog()~**

Теперь вызовем  функцию **~newFunc()~**, передав ей функцию **~elefant()~**:

~~~js
newFunc(elefant, 'sample')
~~~

В результате на странице появится новый элемент с текстом, который возвращает функция **~elefant()~**.

### ![ico-20 icon] Функция-возвращаемое значение⟪A_function_as_a_return_value⟫

Теперь объявим функцию **~createFunction()~**, которая будет возвращать функцию:

◘◘![ico-25 cap] ** 4**◘◘

~~~js
function createFunction (param) {
  return function () {
    console.log('function ', param)
  }
}
~~~

и создадим с ее помощью две новые функции: **~firstFunc()~** и **~secondFunc()~**:

~~~js
var firstFunc = createFunction('First')
var secondFunc = createFunction('Second')
~~~

Вызовем каждую из этих функций:

~~~js
firstFunc()
secondFunc()
~~~

В консоли мы увидим:

~~~console
function  First
function  Second
~~~

### ![ico-20 icon] Цепочные вычисления⟪Chain_computations⟫

Следующий пример демонстрирует возможность создания цепочных вычислений с помощью функции высшего порядка:

◘◘![ico-25 cap] **5**◘◘

~~~js
function first (a, b, c) {
  if (!a || typeof a !== 'number') {
      return first
  }
  if (!b || typeof b !== 'number') {
    return function second (b, c) {
      if (!b || typeof b !== 'number') {
        return second
      }
      if (!c || typeof c !== 'number') {
        return function third (c) {
          if (!c || typeof c !== 'number') {
            return third
          }
          return a + b + c
        }
      } else {
        return a + b + c
      }
    }
  } else {
    if (!c || typeof c !== 'number') {
      return function third (c) {
        if (!c) return third
        return a + b + c
      }
    } else {
      return a + b + c
    }
  }
}

console.log('first(5, 10, 20):', first(5, 10, 20))
console.log('first(5)(10)(20):', first(5)(10)(20))
~~~

~~~console
first(5, 10, 20): 35
first(5)(10)(20): 35
~~~

Функция **~first()~** ожидает три числовых аргумента. В случае, если ее вызвали без аргументов или аргументы не являются числами, она возвращает саму себя.
В случае, если ей передан только один аргумент, она возвращает функцию **~second()~**, которая ждет уже два числовых аргумента, поскольку первый уже есть в ее области видимости (scope).
Если при вызове функции **~second()~** не передано ни одного аргумента или эти аргументы не являются числами, то она возвращает саму себя.
Если при вызове функции **~second()~** ей передан только один аргумент, то она возвращает функцию **~third()~**, которая ждет уже только один числовой аргумент, потому что два первых уже есть в ее области видимости (scope).
Если при вызове функции **~third()~** ей не передано числовой аргумент, она вернет саму себя.
В случае передачи функции **~third()~** числового аргумента она вернет сумму всех трех аргументов.

~~~js
const second = first(5)
const third = second(10)
console.log('third(20):', third(20))
~~~

~~~console
third(20): 35
~~~

~~~js
console.log('first("a", "b", "c")')
console.dir(first('a', 'b', 'c'))
~~~

~~~console
first("a", "b", "c")
▼ ƒ first(a, b, c)
    length: 3
    name: "first"
  ► prototype: {}
    arguments: null
    caller: null
  ► [[Prototype]]: ƒ ()
~~~

~~~js
console.log('first(5, 10, "*"):')
console.dir(first(5, 10, '*'))
~~~

~~~console
▼ ƒ third(c)
    length: 1
    name: "third"
  ► prototype: {}
    arguments: null
    caller: null
  ► [[Prototype]]: ƒ ()
~~~

Обратите внимание, как в процессе цепочных вычислений функция **~first()~** фильтрует "мусор":

~~~js
first('*')(undefined)(5)(NaN)(7)(false)(null)(3)
~~~

~~~console
15
~~~
