## ![ico-25 icon] arguments

У літеральній нотації об’єкт описується всередині блоку фігурних дужок:

![ico-25 cap]

~~~js
var figure = {
  type: 'circle',
  radius: 100,
  color: 'red'
}
~~~

Усі ці властивості доступні ззовні:

~~~js
console.log(figure.type)
console.log(figure.radius)
console.log(figure.color)
~~~

або так:

~~~js
console.log(figure['type'])
console.log(figure['radius'])
console.log(figure['color'])
~~~

![ico-20 pin] Властивості об’єктів, заданих літералом, є **публічними**, оскільки вони доступні ззовні

![ico-25 cap] Хоча завжди є спосіб це обійти ![ico-25 smile]

^^^[Closure]

~~~js
var sample = {
  path: 'https://garevna.github.io/js-lessons/icons/',

  testToken: (function (token) {
    return function () {
      return prompt('Input Your Token: ') === token
    }
  })(prompt('Set Your Token: ')),

  page: function () {
    const ico = this.testToken() ? 'green-ok.png' : 'no_entry.png'
    document.write(`<img src="${this.path}${ico}">`)
  }
}

sample.page()
~~~

^^У цьому прикладі під час створення об’єкта запитується введення токена доступу, який буде збережено в замиканні методу **testToken**^^

^^при спробі отримати доступ до сторінки (властивості **page**) буде викликано метод **testToken**, який запросить токен доступу та звірить його зі значенням, що зберігається у замиканні^^

^^Якщо значення збігатимуться, то на сторінці з’явиться ![ico-25 green-ok]^^

^^В іншому разі на сторінці з’явиться ![ico-25 err]^^

^^^

### ![ico-20 icon] Власні властивості

Власні властивості _інкапсульовані_ в екземплярі

Наприклад, екземпляр **~figure~** виступає в ролі «капсули», в якій властивості **~type~**,  **~size~**  та  **~color~**  відокремлені від таких самих властивостей інших екземплярів

Можна створити об’єкт **~figure2~** з таким самим набором властивостей, але з іншими значеннями цих властивостей:

◘◘![ico-25 cap] 1◘◘

~~~js
var figure2 = {
  type: 'triangle',
  size: 150,
  color: 'blue'
}
~~~

У екземплярів **~figure~** та **~figure2~** однаковий набір властивостей (імена властивостей збігаються)

Однак значення цих властивостей у кожному екземплярі відрізняються

Отже, **_власні властивості екземпляра — це властивості, інкапсульовані в цьому екземплярі_**

^^властивості  **_~type~_**,  **_~size~_**  та  **_~color~_**  є **власними** властивостями екземплярів  **~figure~**  та  ** ~figure2~**, оскільки їхні значення локалізовані всередині «капсули» під ім’ям екземпляра )^^

~~~js
figure.type       // "circle"
figure2.type      // "triangle"
~~~

### ![ico-20 icon] Перелічувані властивості

**Перелічувані** властивості екземпляра — це властивості, які ітеруються оператором циклу  **~for...in~**

![ico-20 warn] За замовчуванням властивості нативних об’єктів, що створюються під час виконання коду, є перелічуваними
![ico-20 warn] Властивості вбудованих нативних об’єктів є неперелічуваними

~~~js
for (var prop in figure) console.log(prop)
~~~

У консоль будуть виведені

~~~console
type
size
color
~~~

![ico-20 pin] Отже, за допомогою літералу об’єкта можна створити **публічні власні перелічувані** властивості екземпляра

Очевидно, що кожен із цих термінів має антонім, тобто мають існувати _приватні_, _невласні_ та _неперелічувані_ властивості

![ico-20 pin] **Приватні властивості** можна створити за допомогою **конструктора**
![ico-20 pin] _Невласні властивості_ — це **успадковані** властивості
^^Щодо створення **_неперелічуваних_** властивостей — ми ще повернемося до цієї теми далі^^

### ![ico-20 icon] Успадковані властивості

◘◘![ico-25 cap] 2◘◘

~~~js
var figure = {
  type: 'circle',
  radius: 100,
  color: 'red'
}
~~~

Якщо «розгорнути» екземпляр **figure** у консолі, то крім власних перелічуваних властивостей ~color~, ~size~ та ~type~ ми побачимо властивість **~&#95;&#95;proto&#95;&#95;~**, яка не була виведена в консоль, коли ми ітерували об’єкт оператором ~for...in~

~~~console
▼{ type: "Окружность", radius: 100, color: "red" }
    color:"red"
    radius:100
    type:"Окружность"
  ► __proto__:Object
~~~

Висновок — це властивість **неперелічувана**

З’ясуємо, чи є ця властивість власною

Значенням цієї властивості є посилання на вбудований нативний об’єкт (конструктор) **~Object~**

Якщо розгорнути властивість **~&#95;&#95;proto&#95;&#95;~**, то в консолі ми побачимо таку картину:

^^^[__proto__]

~~~console
▼ __proto__
   ► constructor: ƒ Object()
   ► hasOwnProperty: ƒ hasOwnProperty()
   ► isPrototypeOf: ƒ isPrototypeOf()
   ► propertyIsEnumerable: ƒ propertyIsEnumerable()
   ► toLocaleString: ƒ toLocaleString()
   ► toString: ƒ toString()
   ► valueOf: ƒ valueOf()
   ► __defineGetter__ ƒ __defineGetter__)
   ► __defineSetter__ ƒ __defineSetter__)
   ► __lookupGetter__ ƒ __lookupGetter__)
   ► __lookupSetter__: ƒ __lookupSetter__()
   ► get __proto__: ƒ __proto__()
   ► set __proto__: ƒ __proto__()
~~~

^^^

Перше, що привертає увагу, — наш екземпляр створено конструктором **~Object~**:

~constructor: ƒ Object()~

Давайте розгорнемо **~Object~** у консолі

^^для цього використовуємо метод ~console.dir~, оскільки **~Object()~** — це конструктор, тобто функція, і метод ~console.log()~ поверне нам ••_ ƒ_ Object() { [native code] }••^^

Зверніть увагу на властивість **_~prototype~_** конструктора **~Object~**

Це об’єкт

Розгорнемо цей об’єкт і подивимося на його вміст:

~~~console
▼ prototype:
   ► constructor: ƒ Object()
   ► hasOwnProperty: ƒ hasOwnProperty()
   ► isPrototypeOf: ƒ isPrototypeOf()
   ► propertyIsEnumerable: ƒ propertyIsEnumerable()
   ► toLocaleString: ƒ toLocaleString()
   ► toString: ƒ toString()
   ► valueOf: ƒ valueOf()
   ► __defineGetter__: ƒ __defineGetter__()
   ► __defineSetter__: ƒ __defineSetter__()
   ► __lookupGetter__: ƒ __lookupGetter__()
   ► __lookupSetter__: ƒ __lookupSetter__()
   ► get __proto__: ƒ __proto__()
   ► set __proto__: ƒ __proto__()
~~~

![ico-20 warn] воно повністю збігається з тим, що ми виявили раніше у властивості **~&#95;&#95;proto&#95;&#95;~** екземпляра **figure**

Продовжимо далі та заглянемо в екземпляр **figure2**

Там ми теж виявимо властивість **~&#95;&#95;proto&#95;&#95;~**

і його вміст буде точно таким самим, як у екземпляра **figure**

Створимо порожній об’єкт

~~~js
var obj = {}
~~~

і розгорнемо його в консолі

Ба! Усі обличчя знайомі! ![ico-25 smile]

Ми бачимо те саме властивість **~&#95;&#95;proto&#95;&#95;~**

У всіх нативних об’єктів JS за замовчуванням є ця властивість

![ico-20 warn] Властивість **~&#95;&#95;proto&#95;&#95;~** об’єктів JS, що створюються _літералом_, — це посилання на властивість **_~prototype~_** конструктора **~Object~**

А що там із _вбудованими_ нативними об’єктами?

Розгорніть у консолі об’єкт **Array**

~~~js
console.dir(Array)
~~~

і ви побачите ланцюжок прототипів

Останньою «ланкою» у ланцюжку прототипів завжди буде **~Object~**

~~~js
console.dir(Array.__proto__.__proto__)  // Object
~~~

«Жирна крапка» наприкінці ланцюжка прототипів — **~null~**

Аналогічна ситуація буде з будь-яким вбудованим конструктором

![ico-20 pin] У вбудованих об’єктів, які не є конструкторами (наприклад, _Math_), ланцюжок прототипів буде коротшим: властивість **~&#95;&#95;proto&#95;&#95;~** буде посиланням на **~Object~**

## ![ico-25 icon] Контекст виклику

Настав час розібратися з тим, що ж таке конструктор

![ico-25 warn] Це функція (_звідси випливає, що там можна щось заховати_)
![ico-25 warn] Щоб вона працювала як **конструктор**, під час виклику перед її іменем потрібно вказати ключове слово **~new~**, і в цьому випадку:
![ico-20 green-ok] їй не потрібен оператор ~return~, але при цьому вона поверне **екземпляр** об’єкта
![ico-20 green-ok] всередині неї **~this~** вказуватиме не на _глобальний об’єкт_, а на **екземпляр**, що повертається
![ico-20 green-ok] усі оголошені всередині неї змінні та функції будуть _інкапсульовані_ у створеному **екземплярі** (_тобто будуть власними властивостями та методами екземпляра_)
![ico-20 green-ok] у неї буде властивість **~prototype~** (_яка буває лише у функцій_)
![ico-20 green-ok] те, що ми помістимо у властивість **~prototype~**, _успадкують_ усі екземпляри

![ico-25 warn] Імена конструкторів зазвичай починають з великої літери

◘◘![ico-25 cap] 3◘◘

~~~js
function Sample (params) {}

var obj = new Sample()
~~~

Виведемо в консоль екземпляр **obj**:

~~~console
▼ Sample {}
    ▼ __proto__:
        ► constructor: ƒ Sample( params )
        ► __proto__: Object
~~~

• ми створили порожній об’єкт класу **Sample** ^^(точніше, ми створили екземпляр об’єкта)^^
• він не має власних властивостей ^^(оскільки в конструкторі нічого не оголошено)^^
• у нього є _ланцюжок прототипів_ — це властивості, вкладені одна в одну  **~&#95;&#95;proto&#95;&#95;~**
• перша «ланка» у ланцюжку прототипів — це посилання на властивість **~prototype~** функції-конструктора **Sample**
• властивість **~prototype~**  функції-конструктора **Sample**  є об’єктом
• це означає, що у нього теж є властивість **~&#95;&#95;proto&#95;&#95;~**
• це вкладене властивість **~&#95;&#95;proto&#95;&#95;~** — наступна «ланка» у ланцюжку прототипів
• воно є посиланням на **Object**

~~~js
Sample.prototype
~~~

~~~console
▼ {constructor: ƒ}
    ► constructor: ƒ Sample(params)
    ► __proto__: Object
~~~

Ми можемо додати властивості до **~prototype~** конструктора **Sample**

~~~js
Sample
  .prototype
  .setNewProperty = function (propName, propValue) {
    this[propName] = propValue
  }
~~~

Якщо тепер вивести в консоль екземпляр **obj**, то в його властивості **~&#95;&#95;proto&#95;&#95;~** ми виявимо нову перелічувану властивість **_~setNewProperty~_** (_успадкований метод_)

Викличемо цей метод:

~~~js
obj.setNewProperty('name', 'Petro')
~~~

і побачимо, що в екземпляра **obj** з’явилася нова _власна перелічувана_ властивість **name**

![ico-20 warn] Під час звернення до властивості спочатку її шукають серед власних властивостей екземпляра, і якщо її не буде знайдено, то пошук продовжиться серед властивостей прототипу, і так далі, доки не закінчиться ланцюжок прототипів

![ico-25 pin] Конструктор дозволяє створювати екземпляри об’єктів, що мають не тільки публічні, але й приватні властивості та методи

## ![ico-25 icon] Публічні та приватні властивості

Конструктор — це функція, з чого випливає, що за допомогою конструктора можна «сховати» змінні та функції
Де сховати? — в екземплярі, створеному за допомогою цього конструктора

Як ми вже знаємо, конструктор створює **_власні_** властивості та методи екземплярів шляхом оголошення змінних і функцій

![ico-25 pin] Усі властивості, оголошені в конструкторі з ключовим словом  **~this~**, будуть **_публічними_**

![ico-25 pin] Усі властивості, оголошені в конструкторі з ключовим словом  **~var~** або **~function~**, будуть **_приватними_**

До публічних властивостей та методів екземпляра завжди є доступ із зовнішнього середовища

Достатньо використати _ім’я екземпляра_ + «.» + _ім’я властивості_ (_методу_)
^^під час виклику методу потрібно ще додати круглі дужки після його імені^^

Приватні властивості (та методи) екземпляра недоступні ззовні

Вони не відображаються в консолі під час виведення об’єкта

◘◘![ico-25 cap] 5◘◘

~~~js
var  Girl = function (name = 'Jane', age = 25) {
  this.name = name
  this.age = age

  function showName (name) {
    console.log(`My name is ${name}`)
  }

  this.changeName = function (newName) {
    this.name = newName
    showName(this.name)
  }
}

var lena = new Girl('Helen', 18)
lena.changeName('Mary')
~~~

У цьому прикладі **_~defaultName~_**  та **_~showName~_** є **_приватними_** властивостями екземпляра **~lena~**

**_~name~_**, **_~age~_** та **_~changeName~_** є **_публічними_** властивостями екземпляра **~lena~**

У публічних методах екземпляра (**_~changeName~_**)  **~this~**  буде посиланням на екземпляр (**~lena~**)

![ico-20 warn] у приватних методах (**_~showName~_**) екземпляра контекстом виклику буде *глобальний об’єкт* **~window~**

(тобто всередині методу **_~showName~_** ** ~this~**  буде посиланням на об’єкт **~window~**)

◘◘![ico-25 cap] 7◘◘

~~~js
var Bag = function (keyword) {
  var money = 3000

  var documents = [
    'Passport',
    'Driver license',
    'University Diploma'
  ]

  var accessories = [
    'Keys',
    'Movie tickets',
    'Medicine'
  ]

  this.content = null

  function getMoney (sum) {
    money -= sum
  }

  this.payment = function (sum) {
    if (prompt('Who are you?') !== keyword) return '⛔️'
    getMoney(sum)
    console.info(`Money left in wallet: ${money} uah`)
    return `Paid: ${sum} uah`
  }

  this.rummage = function () {
    this.content = [
      documents,
      accessories,
      money
    ]
    console.log(`Search protocol. Bag contents: ${this.content}`)
  }
}

var myCase = new Bag('it\'s me, your mistress')
~~~

^^Конструктор **~Bag~**  створює об’єкт із приватними властивостями  **~money~**,  **~documents~** та  **~accessories~**^^

^^За його допомогою створюємо екземпляр **myCase**^^

^^Під час створення екземпляра передаємо йому ключову фразу для доступу до вмісту сумочки “_це я, твоя господиня_”^^

^^Оскільки властивості  **~money~**,  **~documents~** та  **~accessories~** є приватними,  «сумочка закрита»^^

^^Стороннім немає доступу до її вмісту^^

^^Публічна властивість **~content~** спочатку має значення  **~null~**^^

^^Це все, що ви можете побачити в закритій сумочці^^

^^Якщо власник сумки погодиться показати її вміст, то його буде розміщено у публічній властивості **~content~** для перегляду^^

^^Функція **~getMoney()~** доступу до грошей  (приватної властивості **~money~**) також є приватною, оскільки ніхто, крім власника, не повинен мати можливості взяти гроші з сумки^^

^^І є два публічні методи:^^

^^• **payment (_sum_, _key_)** — оплата^^
^^• **rummage ()** — митний огляд^^

^^У разі здійснення платежу за допомогою публічного методу **payment**^^

~~~js
console.log(myCase.payment(2000))
~~~

^^запитується ключова фраза, порівнюється з тією, що була встановлена під час створення екземпляра, і якщо значення збігаються, то викликається приватний метод **~getMoney~**, який зменшує приватну властивість ** ~money~** на суму платежу,  після  чого публічний метод **~pay()~** з чистою совістю повертає вилучену суму^^

^^Якщо буде введено неправильну ключову фразу, то запит буде відхилено з поверненням ![ico-20 err]^^

^^У разі митного огляду викликається публічний метод **rummage()**^^

~~~js
myCase.rummage ()
~~~

^^який «викладає на огляд» вміст сумочки (поміщає його в публічну властивість **~content~**)^^

^^Тепер працівники митниці можуть переглянути вміст:^^

~~~js
console.log(myCase.content)
~~~
