## ![ico-30 study] RAIL⟪RAIL⟫

Скільки пам’яті «споживає» додаток на клієнті?
![ico-20 warn] Якщо обсяг використовуваної пам’яті зростає пропорційно до часу роботи додатка, це свідчить про витоки пам’яті.
![ico-20 warn] Якщо додаток часто «зависає» на секунду-дві, то, найімовірніше, занадто часто запускається збирач сміття, щоб очистити пам’ять від непотрібних тимчасових даних.

**RAIL** — це модель продуктивності, орієнтована на користувача.
Вона розбиває взаємодію користувача на ключові дії:

|  **Response**  |  **Animation**  |  **Idle**  |  **Load**  |

Основні характеристики продуктивності з точки зору користувача:

![ico-20 green-ok] Швидкість завантаження сторінки
• час відтворення (візуалізації) контенту
• час до того, як сторінка стане інтерактивною, тобто почне реагувати на дії користувача
![ico-20 green-ok] плавність анімації (бажано 60 кадрів на секунду)
![ico-20 green-ok] інтерактивність сторінки
час від моменту, коли користувач виконав якусь дію на сторінці, до моменту, коли додаток відреагує на цю дію, має бути в межах 100 мс
більш тривала затримка буде дратувати

**Chrome DevTools** надає детальний аналіз усього, що відбувається під час завантаження та запуску додатка

### ![ico-20 icon] Performance⟪Performance⟫

**^^First Contentful Paint^^** — час до того моменту, коли перший текст або зображення з’явиться на сторінці
**^^First Meaningful Paint^^** — час, необхідний для відображення основного вмісту сторінки користувачеві
**^^Speed Index^^** — індекс швидкості завантаження сторінки (наскільки швидко відображається вміст сторінки): чим менше значення, тим краще
**^^First CPU Idle^^** (**^^First Interactive^^**) — час першого простою процесора
мінімальна інтерактивність сторінки,
тобто коли більша частина, але, можливо, ще не всі елементи інтерфейсу є інтерактивними, 
сторінка реагує в середньому на більшу частину користувацьких дій у розумні терміни
**^^Time to Interactive^^** — час до досягнення інтерактивності (скільки часу потрібно сторінці, щоб стати інтерактивною)
Це означає, що:
• на сторінці відображено корисний контент (First Contentful Paint);
• для найбільш помітних елементів інтерфейсу зареєстровано обробники подій;
• сторінка реагує на дії користувача протягом 50 мілісекунд
**^^Max Potential First Input Delay^^** (перша затримка вводу) — час від моменту, коли користувач вперше взаємодіє з сторінкою
(тобто клікає на посилання, кнопку тощо), до моменту, коли браузер зможе відповісти на цю дію
^^причиною затримки є те, що головний потік браузера може бути зайнятий іншою задачею^^

Вкладка **^^Performance^^** відображає часову шкалу записаного фрагмента роботи додатку

## ![ico-25 icon] Memory⟪Memory⟫

[%%%How to Record Heap Snapshots%%%](https://developers.google.com/web/tools/chrome-devtools/memory-problems/heap-snapshots)
[%%%Fix Memory Problems%%%](https://developers.google.com/web/tools/chrome-devtools/memory-problems/)

Розглянемо приклад коду, продуктивність якого ми хочемо протестувати:

~~~~js
const segments = [[1, 8], [2, 3], [4, 7], [5, 6], [2, 8], [3, 7], [4, 6], [1, 5], [1, 6]]

function countInnerIntervals (intervals) {
  const results = []

  intervals
    .forEach((segment, index, array) => results.push(array.reduce((childs, section) => array.filter(item => item[0] > segment[0] && item[1] < segment[1]).length)))
  return results
}
~~~~

Нас цікавить не лише час виконання функції **~countInnerIntervals~**, а й витрати пам’яті

Для цього додамо кнопку на сторінку:

~~~~js
const button = document.body
  .appendChild(document.createElement('button'))

button.innerText = 'Start'

button.onclick = function (event) {
  console.time('segments')
  const children = countInnerIntervals(segments)
  console.timeEnd('segments')
  console.log(children)
}
~~~~

При натисканні на кнопку викликається функція **~countInnerIntervals~**

Виклик **~countInnerIntervals~** обгортається в ~console.time~/~console.timeEnd~, що дозволить нам отримати приблизну оцінку часу виконання функції
