## ![ico-25 icon] Об’єкт arguments

Функції JavaScript мають вбудований об’єкт **~arguments~**.
Він має властивість **~length~**, як і масив.
Його елементи доступні за індексом, як і елементи масиву.

![ico-20 warn] Однак це не масив.

^^Тому до нього не можна застосовувати методи роботи з масивами (**~push~**, **~pop~** тощо)^^
^^Його можна перетворити на звичайний масив за допомогою методу **~Array.from~**^^

~~~js
function test () {
  var args = Array.from(arguments)
  ...
}
~~~

В об’єкті **~arguments~**  знаходяться всі аргументи, передані функції під час її виклику.
Вони будуть доступні за індексом строго в тому порядку, в якому вони були передані функції під час виклику.

♦♦♦1♦♦♦

~~~js
function testArguments () {
  for (var i = 0; i < arguments.length; i++) {
    console.log(`[${ (i + ' ]').padEnd(10) } ${ arguments[i] }`)
  }
}

testArguments(27, false, 'Fill', [7, 4, 5], null)
~~~

### ![ico-20 icon] arguments.callee

Об’єкт **~arguments~** має властивість **_~callee~_** — посилання на функцію, що виконується (функцію-«господаря» об’єкта  ~arguments~).

~~~js
function testArguments () {
  console.log(arguments.callee.name)
}

testArguments() // testArguments
~~~

^^^[Приклад 2]

^^Оголосимо функцію  **~getArguments~**:^^

~~~js
function getArguments (param) {
  return param ? param : arguments.callee
}
~~~

^^яка, якщо їй було передано аргумент, повертає значення цього аргументу, в іншому випадку повертає посилання на саму себе.^^

^^Тепер викличемо цю функцію з параметром і без:^^

~~~js
var x = getArguments()
var y = getArguments('Привет!')
~~~

^^результат виклику функції без аргументів ми помістили в змінну  **~ x ~**,^^
^^а результат виклику з аргументом «Привіт!» ми помістили в змінну  **~ y ~**^^

^^Тепер виведемо в консоль змінні **~ x ~** та **~ y ~**^^

^^У змінній **~ x ~** міститься точна копія функції **~getArguments~**^^

^^а в змінній **~ y ~** — рядок «Привіт!»^^

^^Викличемо функцію **~ x ~**:^^

~~~js
x('До свидания!')
~~~

і отримаємо рядок «До побачення!»

^^^

^^^[Приклад 3]

![ico-25 cap] ** 3 **

^^Оголосимо функцію, яка «сама себе лікує», тобто сама додає собі властивості та методи:^^

~~~js
function setProperty (prop, val) {
  arguments.callee[prop] = val
}
~~~

^^Тепер змусимо її створити собі кілька властивостей:^^

~~~js
setProperty('isActive', false)
setProperty('value', 50)
~~~

^^Ну, і для більшої переконливості змусимо її створити собі метод:^^

~~~js
setProperty('method', function () {
  console.log('А еще я умею вышивать крестиком')
})
~~~

^^тут ми передаємо їй як другий аргумент функцію^^

^^Тепер перевіримо, що ці властивості та метод з’явилися у функції  **~setProperty~**^^

^^Виведемо в консоль властивості **~isActive~** і **~value~**   функції  **~setProperty~**  та викличемо її метод  **~method~**^^

^^^

^^^[Приклад 4]

![ico-25 cap] ** 4 **

^^Створимо функцію, яка «накопичує» результати власних обчислень^^

^^Нехай це буде функція, що обчислює факторіал числа^^

~~~js
var factorial = function (num) {
  var res = 1, n = 1
  while (n <= num) res *= n++
}
~~~

^^«Модифікуємо» її наступним чином:^^

~~~js
var factorial = function (num) {
  if (!arguments.callee.res) arguments.callee.res = []
  var res = 1, n = 1
  while (n <= num) res *= n++
  arguments.callee.res.push(res)
  return res
}
~~~

^^Викличемо її з різними значеннями аргументу та виведемо в консоль значення властивості **~res~**:^^

~~~js
factorial(5)
factorial(5)

console.log(factorial.res)
~~~

^^Отримаємо масив ~[120, 3628800]~^^

^^^

^^![ico-20 warn] Наступний приклад краще розглянути після вивчення подій елементів DOM^^

^^^[Приклад 5]

![ico-25 cap] ** 5 **

^^У цьому прикладі створюються анонімні функції, які обробляють подію **~click~**  кнопок^^

^^Кожна функція «накопичує» дані про час кліка на кнопці в масиві **~arguments.callee.res~**^^

~~~js
var buttons = []

for (var n = 0; n < 5; n++) {
  buttons[n] = document.body
    .appendChild(document.createElement('button'))
  buttons[n].innerText = n
  buttons[n].onclick = function (event) {
    if (!arguments.callee.res) arguments.callee.res = []
    arguments.callee.res.push(Math.round(event.timeStamp))
    console.log(arguments.callee.res)
  }
}
~~~

^^Модифікуємо цей код:^^

~~~js
var buttons = []

for (var n = 0; n < 5; n++) {
  buttons[n] = document.body
    .appendChild(document.createElement('button'))
  buttons[n].innerText = 0
  buttons[n].style = 'padding: 8px 16px'
  buttons[n].onclick = function (event) {
    var func = arguments.callee
    if (!func.clicksTime) func.clicksTime = []
    func.clicksTime.push(Math.round(event.timeStamp))
    console.log(func.clicksTime)
    var len = func.clicksTime.length
    event.target.innerText = len
    func.res = len > 1
      ? func.clicksTime[len - 1] - func.clicksTime[len - 2]
      : 0
    console.info(`Интервал между последними кликами: ${func.res}`)
  }
}
~~~

## ![ico-25 icon] Об’єкт, що викликається

У цьому сенсі функцію можна порівняти з ![ico-30 ambulance]
Як і ![ico-20 ambulance], функція може переміщатися від одного об’єкта до іншого (звідки вона викликана).

При цьому об’єкти, що викликають функцію, є **контекстом виклику**.

Сама функція повинна мати «інструменти» для виконання свого завдання в контексті виклику.

Усі ці інструменти, що не належать до контексту виклику, а перебувають виключно у розпорядженні функції, належать до **контексту виконання**.

Отже, куди поїде ![ico-20 ambulance] — це **контекст виклику**.
Те, що знаходиться всередині ![ico-20 ambulance] — це **контекст виконання**.

^^^[Контекст виконання]

![ico-30 ambulance]

| **властивості** ^^(змінні)^^ | **методи** ^^(функції)^^ |
| ^^набір інструментів, медикаментів, перев’язувальних матеріалів, різних приладів (крапельниці, дефібрилятор, апарат штучного дихання тощо) ^^ | ^^професійні навички персоналу машини швидкої допомоги (можуть зробити укол, поставити крапельницю, застосувати дефібрилятор, перенести хворого на ношах тощо)^^ |

^^Все це функція ![ico-20 ambulance] везе з собою^^

^^^

^^^[Контекст виклику]

![ico-30 ambulance]

^^• конкретні умови (приватний будинок, квартира у багатоповерхівці, наявність або відсутність ліфта, водопроводу тощо)^^
^^• конкретний хворий із конкретними симптомами, віком, історією хвороби, характером тощо^^

## ![ico-25 icon] Контекст виклику

Контекст виклику — це **об’єкт**.

Зазвичай під час виклику функції ім’я цього об’єкта стоїть перед ім’ям функції й відокремлене від нього крапкою:

~~~js
patient.emergency()
~~~

Як правило, якщо ім’я об’єкта перед ім’ям функції не вказано, то контекстом виклику функції є глобальний об’єкт **~window~**.

^^Виняток становлять функції, контекст виклику яких встановлюється за допомогою методу ~bind()~.^^

![ico-20 warn] Звідси випливає, що всі функції JS є методами
Якщо об’єкт («господар» методу) не вказано, мається на увазі глобальний об’єкт

_______________________________

^^^[Приклад 6]

![ico-25 cap] ** 6 **

^^Оголосимо три функції:^^

~~~js
function first () {
  console.log('Function "first" is working now.')
}
function second () {
  console.log('Function "second" is working now.')
}
function third () {
  console.log('Function "third" is working now.')
}
~~~

^^Усі три функції оголошені в глобальному контексті, тобто вони є методами глобального об’єкта **~window~**.^^

^^Як ми вже знаємо, можна звертатися до властивостей об’єкта як до елементів асоціативного масиву.^^

^^Тоді конструкція:^^

~~~js
window['first']
~~~

^^поверне нам функцію  **~first~**, яка є властивістю (методом) глобального об’єкта **~window~**.^^

^^Для виклику цієї функції бракує лише круглих дужок:^^

~~~js
window['first']()
~~~

^^Використовуючи цей факт, ми можемо викликати функцію, ім’я якої нам передано у змінній типу «_string_»:^^

~~~js
for (var funcName of ['first', 'second', 'third']) window[funcName]()
~~~

### ![ico-20 icon] Посилання на контекст виклику

Під час виклику бригади швидкої допомоги вона отримує посилання на об’єкт виклику.

Бригаді потрібно знати, куди їхати, симптоми хворого, вік тощо.

Точно так само функція повинна мати доступ до об’єкта, який її викликає, та до його властивостей, які можуть бути необхідними для нормальної роботи функції.

Усередині функції ключове слово **~this~** є посиланням на об’єкт, у контексті якого викликано функцію (тобто на контекст виклику).

## ![ico-25 icon] Контекст виконання

![ico-20 warn] Кожен виклик функції призводить до створення нового контексту виконання.

Створення контексту виконання відбувається до початку виконання коду.

При кожному поверненні (**~return~**) відбувається вихід із контексту виконання.
Поки виконання функції не завершено, її контекст залишатиметься активним.
Оскільки функції можуть викликати одна одну, їхній контекст розміщується у стеку.

### ![ico-20 icon] Lexical Environment

^^Коли відбувається виклик функції, вона активується.^^
^^Їй потрібно десь безпечно «розмістити» свої дані, з якими вона працюватиме.^^
^^Окрім аргументів, які вона отримає під час виклику, вона може мати власні внутрішні дані, необхідні для тимчасового зберігання проміжних результатів обчислень.^^

Під час виклику функції створюється об’єкт, що містить усі необхідні змінні.
Цей об’єкт у специфікації мови називається **~LexicalEnvironment~.**

~Lexical Environment~ містить аргументи функції та всі змінні, оголошені всередині функції (включно з функціями).

^^Тому його ще називають _об’єктом змінних_ або _об’єктом активації_.^^

^^Таким чином, об’єкт активації можна порівняти з шафкою для зберігання «особистих речей» функції.^^

^^![ico-20 warn] Отримати доступ до об’єкта активації неможливо.^^

______________________________________________

### ![ico-20 icon] hoisting

Отже, після виклику функції:

| ** 1** |   | **Формується контекст виконання**                      |
|        | • | ^^створюється об’єкт активації ( ~Lexical Environment~ )^^ |
|        | • | ^^визначається область видимості^^                       |
|        | • | ^^встановлюється значення **~this~**^^                  |
| ** 2** |   | **Код інтерпретується та виконується**                   |

![ico-20 warn] Зверніть увагу на те, що оголошення всіх внутрішніх змінних та вкладених функцій відбувається раніше, ніж код починає виконуватися, незалежно від порядку їх появи в коді.
![ico-20 warn] А ось присвоєння змінним значень відбувається, коли код починає виконуватися.
Це призводить до «підняття» (**hoisting**) оголошень змінних і функцій.

^^^[Приклад 7]

![ico-25 cap] ** 7 **

~~~js
function delegat () {
  console.log(x)
  y = x + 5
  console.log(y)
  x = 5, y = 10

  return  x * 4 +  y / 2

  var x = 1, y = 1
}
~~~

^^Хоча оголошення змінних  **_~ x~_** та **_~ y~_** розміщене в коді після оператора ~return~, під час формування контексту виконання на першому етапі формуватиметься об’єкт активації (Lexical Environment), і всі змінні, оголошені всередині функції, будуть включені до цього об’єкта.^^

^^Таким чином, оголошення змінних **_~ x~_** та **_~ y~_** «підніметься» (відбудеться до початку виконання коду функції).^^

^^Але присвоєння значень відбувається вже на другому етапі, і код виконуватиметься послідовно, тобто на момент виконання коду.^^

~~~js
console.log(x)
~~~

^^значення змінної  **_~ x~_**  ще не буде визначено, тому в консолі буде ~undefined~.^^

^^Аналогічно, на момент виконання коду^^

~~~js
y = x + 5
~~~

^^значення змінної  **_~ x~_**  буде  ~undefined~, тому результатом операції присвоєння буде  **~NaN~**,  що й видасть у консоль код.^^

~~~js
console.log(y)
~~~

^^Після цього буде виконано код^^

~~~js
x = 5, y = 10
~~~

^^Змінні **_~ x~_** та **_~ y~_** отримають значення.^^

^^Тому функція поверне значення **25**.^^

^^Присвоєння значень^^

~~~js
x = 1, y = 1
~~~

^^не відбудеться, оскільки вихід із контексту виконання відбудеться раніше, ніж цей код.^^

^^^

^^^[Приклад 8]

![ico-25 cap] ** 8**

~~~js
var treg = 5

function delegat () {
  treg = 10
  return

  function treg () {
    return
  }
}
delegat()
console.log(treg)  // 5
~~~

^^У цьому випадку оголошення функції  **~treg~**  потрапить у _Lexical Environment_ функції  **~delegat~** на етапі створення її контексту виконання і не торкнеться змінної  **~treg~**,  оголошеної в глобальному контексті.^^

^^Це будуть різні змінні,  хоча їхні ідентифікатори збігаються.^^

^^Тому  у результаті в консолі буде ** 5**.^^

^^^

### ![ico-20 icon] Область видимості

Область видимості (**~scope~**) обмежує дію ідентифікаторів змінних і функцій.

^^^[scope]

^^Уявіть собі двох людей на ім’я Саша: 👨‍💼 хлопця та 🙎 дівчину^^

^^Є дві кімнати, ^^
^^і хлопець Саша  👨‍💼 перебуває в першій кімнаті, ^^
^^а дівчина Саша 🙎 — у другій^^

^^У кожній кімнаті є спостерігач^^

^^Якщо ми запитаємо спостерігача з першої кімнати: ^^
^^_«Ким є Саша?»_, ^^
^^то він відповість: _«Хлопець»_ 👨‍💼^^

^^Задамо аналогічне запитання спостерігачеві з другої кімнати, ^^
^^і отримаємо відповідь: _«Дівчина»_ 🙎^^

^^Це відбувається тому, що кожна кімната має свою зону видимості^^

_________________________________

^^Однак зона видимості вкладених функцій буде дещо іншою^^

^^Припустимо, що вкладені функції — це коробки зі стінками з тонованого скла^^
^^Наші функції-коробки вкладені одна в одну, як матрьошки: ^^
^^друга коробка знаходиться всередині першої,^^
^^третя — всередині другої, і так далі...^^

^^Спостерігач у коробці 2 бачитиме не лише вміст коробки 2, ^^
^^а й вміст коробки 1 ^^
^^та кімнати, всередині якої знаходяться всі коробки^^

^^але він не може побачити вміст коробки 3, ^^
^^хоча спостерігач у коробці 3 його чудово бачить... ^^
^^як і спостерігачів у всіх інших коробках ^^
^^і в кімнаті^^

____________________________

^^Таким чином, якщо всередині функції буде звернення до змінної, то спочатку функція шукатиме цю змінну у своїй «шафці для особистих речей», і якщо не знайде, то не соромитиметься «позичити» цю змінну із зовнішньої шафки, всередині якої вона знаходиться^^

^^^

^^^[Приклад 9]

![ico-25 cap] ** 9**

~~~js
var sample = 1

function changeSample () {
  sample = 10
}

changeSample()
~~~

^^змінна **~sample~**   оголошена в глобальній області видимості, в якій  також оголошена функція **~changeSample~**.^^

^^Під час оголошення змінної **~sample~** їй присвоєно значення 1.^^

^^Оскільки всередині функції **~sample~**  немає оголошення змінної **~changeSample~**, то під час формування контексту виконання функції **~changeSample~** ця змінна не потрапляє в об’єкт активації («шафка для особистих речей») функції **~changeSample~**.^^

^^Тоді під час виконання присвоювання^^

~~~js
sample = 10
~~~

^^відбувається наступне:^^

^^функція **~changeSample~**, не знайшовши такої змінної у власному «шафці», звертається до зовнішнього «шафця», де така змінна є, і саме їй буде присвоєно значення 10.^^

^^Таким чином, для кожного контексту виконання існує свій ланцюжок областей видимості.^^

^^Ланцюжок областей видимості включає області видимості всіх попередніх контекстів у стеку.^^

^^^

^^^[Приклад 10]

![ico-25 cap] **10**

~~~js
var sample = 1

function showSample () {
  console.info('We are in the execution context of the function "showSample"')
  console.info(`sample === ${sample}`)

  return

  function sample () {}
}

showSample()

console.info('We left the execution context of the function "showSample"')
console.info(`Now sample === ${sample}`)
~~~

**Результат у консолі:**

~~~console
We are in the execution context of the function "showSample"
sample === function sample () {}
We left the execution context of the function "showSample"
Now sample === 1
~~~

^^У цьому прикладі показано, як працює механізм **hoisting**.^^
^^Змінна **~sample~** оголошується в глобальній області видимості з присвоєнням їй значення 1.^^
^^Усередині тіла функції **~showSample~** після оператора return оголошується функція **~sample~**.^^
^^На перший погляд, при послідовному виконанні коду це оголошення не повинно спрацювати, оскільки оператор ~return~ стоїть вище.^^
^^Однак усі оголошення збираються в об’єкт активації до того, як код починає виконуватися.^^
^^Тому на момент, коли почнеться виконання коду функції **~showSample~**, функція **~sample~** буде вже оголошена і благополучно перебуватиме в ~Lexical Environment~ функції **~showSample~**.^^
^^Завдяки цьому оголошення змінних і функцій «піднімаються» в область видимості «батька» (у нашому випадку «батьком» є функція **~showSample~**).^^
^^Переконатися в цьому дозволяє виведення в консоль змінної **~sample~**.^^
^^Після завершення виконання коду функції **~showSample~** її контекст буде «демонтований», і знову активним стане глобальний контекст, у якому  змінна **~sample~**  має значення 1.^^

^^^

^^^[Приклад 11]

![ico-25 cap] **11**

~~~js
var sample = 1

function showSample () {
  console.info('We are in the execution context of the function "showSample"')
  console.info(`(1) ${sample}`)
  sample()
  console.info(`(2) ${sample}`)
  sample = 10
  console.info(`(3) ${sample}`)

  return

  function sample () { sample = 5 }
}

showSample()

console.info(`(global) ${sample}`)
~~~

^^Тут також відбувається підняття оголошення функції **~sample()~**.^^
^^Але функція  **~sample()~**  перевизначає значення  змінної  **~sample~**.^^
^^У контексті виконання функції  **~showSample~** на момент присвоєння змінній **~sample~** значення 5 немає іншої оголошеної змінної **~sample~**, крім самої функції  **~sample()~**.^^
^^Таким чином, до виклику функції  **~sample()~** у консоль буде виведено функцію.^^
^^Після виклику функції  **~sample()~** у консоль буде виведено нове значення (5) змінної **~sample~**.^^
^^Після цього буде виконано присвоєння нового значення змінній **~sample~**  та виведення в консоль (10).^^
^^Коли функція **~showSample~** завершить роботу, і її контекст буде «демонтований», стане активним глобальний контекст, у якому змінна **~sample~** має значення 1.^^

^^У цьому прикладі функція **~sample()~** перевизначила саму себе (була «function», стала «number»).^^

^^^

### ![ico-20 icon] Ланцюжок областей видимості

Отже, функція може використовувати певні змінні, яких немає в її ~LexicalEnvironment~.

^^Вони є зовнішніми і знаходяться в іншому контексті.^^
^^Але вони доступні функції.^^
^^Функція «бачить» їх, тому вони знаходяться в її _області видимості_.^^

^^Коли всередині функції відбувається звернення до змінної або функції, насамперед движок шукатиме цю змінну в ~LexicalEnvironment~ функції; якщо її там не буде — пошук продовжиться по ланцюжку областей видимості.^^

^^Якщо змінну (або функцію) не буде виявлено, буде згенеровано виняток ![ico-20 err] ~ReferenceError~.^^

### ![ico-20 icon] this

**~this~** — це ще одна складова контексту виконання функції.

**~this~** є посиланням на контекст виклику функції.

![](slogans/reference-is-a-lockpick.svg)

За допомогою ключового слова  **~this~**  можна отримати доступ із функції (або методу) до властивостей об’єкта, у контексті якого було викликано функцію.

_______________________________

![ico-25 cap] **12**

~~~js
function func () {
  console.log(this)
}
~~~

При виклику функції  **~func()~** у консоль буде виведено об’єкт  ~window~.
Усередині  функції  **~func()~** ~this~ вказує на об’єкт  ~window~.

________________________________

![ico-25 cap] **13**

~~~js
function func () {
  child()

  function child () {
    console.log('child this: ', this)
  }
}

func()  // window
~~~

___________________________________

![ico-25 cap] **14**

Якщо ж функція є методом об’єкта, то її контекстом виклику буде цей об’єкт.

~~~js
var human = {
  name: 'Ivan',
  say: function () {
    console.log('this: ', this)
  }
}

human.say() // будет выведен объект  human
~~~

________________________________

![ico-25 cap] **15**

Тепер розглянемо функцію як об’єкт.

~~~js
function say () {
  console.log('function say: this: ', this)
}

function girl () {
  console.log('function girl: this: ', this)
}
~~~

Додамо до функції **~girl~** властивість **~say~** і викличемо функцію ~girl~ та її властивість ~say~:

~~~js
girl.say = say
girl.say()     //  girl
girl()         // window
~~~

## ![ico-25 icon] prototype

• Функцію як **_об’єкт_** не можна вивести за допомогою методу ~console.log~
• Для цього слід використовувати метод **~console.dir~**

~~~js
function sample () {}

console.dir(sample)
~~~

У консолі ми отримаємо таке зображення:
~~~console
▼ ƒ sample()
      arguments: null
      caller: null
      length: 0
      name: "sample"
    ▼ prototype:
        ▶ constructor: ƒ sample()
        ▶ __proto__: Object
    ▶ __proto__: ƒ ()
      [[FunctionLocation]]: VM476:1
    ▼ [[Scopes]]: Scopes[1]
        ▶ 0: Global {type: "global", name: "", object: Window}
~~~

![ico-25 warn] Зверніть увагу на властивість **_~prototype~_**, яка є **лише у функцій**.
![](slogans/function-balls.svg)
![ico-20 pin] властивість **_~prototype~_** функцій — це об’єкт.
![ico-20 pin] у цьому об’єкті є властивість **~constructor~**.
![ico-20 pin] властивість **~constructor~** — це посилання на саму функцію **_~sample()~_**.

Таким чином, функція генетично є конструктором, що явно прописано в її властивості **_~prototype~_**.

_____________________

Зверніть також увагу на властивість **~&#95;&#95;proto&#95;&#95;~**, яку ми розглянемо далі
![ico-20 pin] це **посилання** на об’єкт, від якого функція успадкувала свої властивості та методи
![ico-20 pin] будь-яка функція створюється вбудованим нативним об’єктом (конструктором) **Function**
^^(що свідчить про те, що функція — це **об’єкт**).^^
![ico-20 pin] властивість **~constructor~** у **~&#95;&#95;proto&#95;&#95;~** — це посилання на **Function**.

^^~[[FunctionLocation]]~ та ~[[Scopes]]~ додає Chrome DevTools для налагодження^^
