# ![ico-50 npm] npm

Менеджер пакетів **npm** — це найбільший у світі реєстр програмного забезпечення
(близько 3 мільярдів завантажень на тиждень)

У реєстрі міститься понад 600 000 пакетів

Розробники відкритого програмного забезпечення з усього світу використовують **npm**
для спільного використання та запозичення пакетів

### ![ico-40 npm] npm init

Ця команда створить файл [**~package.json~**](https://docs.npmjs.com/files/package.json) у поточній папці
^^Спочатку потрібно створити нову папку для проєкту та перейти до неї^^

![ico-20 warn] **~package.json~** зберігає залежності проєкту, тобто список пакетів, необхідних для проєкту
^^( для кожного пакета вказано потрібну версію )^^

^^Під час створення файлу **~package.json~** **npm** задасть низку запитань про проєкт,^^
^^який буде розташований у поточній папці^^

^^Ваші відповіді будуть використані для встановлення значень полів:^^

|•| **~name~**        | ^^назва проєкту^^ |
|•| **~version~**     | ^^версія^^ |
|•| **~description~** | ^^короткий опис^^ |
|•| **~author~**      | ^^автор (ви)^^ |
|•| **~repository~**  | ^^посилання на репозиторій проєкту^^ |
|•| **~keywords~**    | ^^ключові слова^^ |
|•| **~scripts~**     | ^^об’єкт, що описує команди запуску скриптів за допомогою **~npm run~**^^ |

^^^[npm init]

![](https://lh4.googleusercontent.com/ZfltZTmbCAsgDdV4IMmNt92vXLdwU5pLyl446vLzdZ5bfuOVx_GIGW-WP2TtxVLriNWUrhkAn2JnNdmYEUszIiQKNkIsGKiuJEfW4t9c3L2-HnhTYjmTaQwW6vmDb1snqoyQ6w0IcjsvR9E)

^^^

^^Оскільки надалі ви зможете редагувати файл **~package.json~**,^^
^^можна не надто перейматися початковими налаштуваннями^^ ![ico-20 wink]

### ![ico-40 npm] package.json

Тепер під час встановлення будь-якого пакета запис про цей пакет автоматично додаватиметься до  розділу **_~dependencies~_**
файлу **~package.json~**

Усі пакети, необхідні для проєкту, будуть описані в розділах

| ![ico-20 folder] | **~dependencies~**    | ^^**залежності пакета**<br>ці пакети будуть безпосередньо включені до збірки додатка^^ |
| ![ico-20 folder] | **~devDependencies~** | ^^**пакети, необхідні на етапі збірки**<br>у сам додаток не вбудовуються^^ |

### ![ico-40 npm] .npmrc

Файл конфігурації, звідки (разом із ~package.json~) npm зчитуватиме налаштування

^^Файл  .npmrc  може існувати для кожного проєкту,^^
^^для кожного користувача,^^
^^та глобально^^

Переглянути налаштування за замовчуванням можна за допомогою команди

••![ico-20 bash] npm config ls -l••

Змінити налаштування можна за допомогою команди

••![ico-20 bash] npm config••

Наприклад, для автоматичного збереження залежностей:

••![ico-20 bash] npm config set save=true••

а для збереження залежностей із зазначенням точної версії пакета:

••![ico-20 bash] npm config set save-exact=true••

### ![ico-40 npm] npm install

У своїх проєктах ви будете використовувати різні пакети, що полегшують життя ![ico-20 wink]

^^Частина цих пакетів знадобиться для збірки вашого додатка,^^
^^його тестування, налагодження, транспіляції тощо.^^
^^Ці пакети не будуть включатися до тіла додатка^^
^^Вони допоможуть це тіло зібрати^^

^^Однак у самому додатку ви будете використовувати сторонні бібліотеки, фреймворки тощо.^^
^^Ці пакети будуть включені до збірки вашого додатка^^

^^Коротше кажучи, усі ці пакети потрібно встановити^^

^^Для цього вам знадобиться команда **~npm install~**^^

___________________________________________________________________________

![ico-20 npm] Опція  **~-g~**  дозволяє встановити пакет **глобально**, щоб він був доступний для всіх ваших додатків

^^![ico-20 pin] **Глобальна інсталяція пакета** з назвою &lt;назва пакета>:^^

••![ico-20 bash] npm install -g &lt;назва пакета>••

^^![ico-20 pin] **Локальна інсталяція пакета** з назвою &lt;назва пакета>:^^

••![ico-20 bash] npm install &lt;назва пакета>••

![ico-20 speach] ^^_Локальна_ — це означає, що пакет буде встановлено в тій директорії (папці проєкту), в якій ви перебуваєте на момент виклику  **~npm~**^^

_____________________________________________________________________________________

![ico-20 npm] Під час встановлення пакетів з опцією _~--save~_   або _~--save-dev~_

**~npm~**   додаватиме відповідні записи до розділу ![ico-20 dir] **~dependencies~**  або  ! [ico-20 dir] **~devDependencies~**

![ico-20 cap] Наприклад, команда

••![ico-20 bash] npm install  -g  css-loader  --save-dev••

### ![ico-40 npm] npm run

Перш ніж використовувати цю команду, потрібно внести певні зміни до файлу **~package.json~**

Конкретніше — у розділ **_~scripts~_**:

~~~js
"scripts": {
    "алиас" : "путь_к_файлу_скрипта"
    ...
}
~~~

У цьому розділі ми описуємо скрипти або пакети, які будемо запускати за допомогою команди  ~npm run~

Ця команда запускає вказаний скрипт

~~~js
"scripts": {
    "start" : "node index.js",
    "build" : "webpack"
}
~~~

## ![ico-40 npm] package-lock.json

Щоразу під час встановлення нової залежності npm автоматично оновлює lock-файл з назвою **_~package-lock.json~_**

**_~package-lock.json~_** — це «зліпок» поточного дерева залежностей, який точно описує дерево папок у директорії ~node_modules~

![warn-25] **_~package-lock.json~_** ніколи не буде опубліковано, навіть якщо його явно включити до збірки

**_~package-lock.json~_** містить поле **_integrity_** для перевірки цілісності пакета

^^Вказання конкретної версії пакета в **_~package.json~_** фіксує залежності лише верхнього рівня^^

^^Якщо ваш додаток запускатиметься на іншому комп’ютері (користувача), то там можуть бути встановлені інші версії пакетів нижчого рівня, що може «зламати» роботу додатка^^

^^Щоб у кінцевого користувача вашого додатка завжди відтворювалося дерево залежностей, ідентичне вашому на момент публікації, слід використовувати **_~shrinkwrap~_** для створення точного знімка цих залежностей і публікації цього знімка разом із додатком^^

![](http://icecream.me/uploads/e5b85cfcb24ca4d34562e1e2ae37ae54.png)

## ![ico-40 npm] npm shrinkwrap

Щоразу, коли виконується розгортання ( _deploy_ ) додатка, Node.js запускає **_npm_**

^^Розгортання може суттєво затягнутися через встановлення нових версій пакетів, зазначених у списку залежностей вашого додатка^^

^^Уникнути оновлення залежностей можна шляхом створення файлу **_npm-shrinkwrap.json_**, який фіксує поточні версії залежностей вашого додатка^^

^^Формат цього файлу повністю ідентичний формату **_~package-lock.json~_**^^

![warn-25] **_~npm-shrinkwrap.json~_** може бути частиною опублікованого пакета

Якщо виконати команду **~npm shrinkwrap~** у папці, в якій уже є **_~package-lock.json~_**,

**npm** перейменує **_~package-lock.json~_** на **_~npm-shrinkwrap.json~_**

Якщо в папці проєкту будуть обидва файли, **npm** використовуватиме **_~npm-shrinkwrap.json~_** та ігноруватиме **_~package-lock.json~_**

[![ico-20 link] npm shrinkwrap](https://javascript.tutorialhorizon.com/2015/03/21/what-is-npm-shrinkwrap-and-when-is-it-needed/)
