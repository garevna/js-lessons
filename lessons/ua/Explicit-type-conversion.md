# ![ico-30 study] Приведення типів⟪Type_coercion⟫

Той факт, що движок дозволяє нам використовувати дані різних типів у виразах, призводить до неприємних наслідків: ми ніколи не можемо бути впевнені в типі даних результату. Така неоднозначність призводить до помилок та збоїв у роботі додатка.
Одним із найнеприємніших наслідків такої неоднозначності є поява підступного значення **~NaN~** (~Not a Number~) у наших обчисленнях.

~~~demo
> var x = 10, y = '***'
< undefined
> x * y
< NaN
~~~

З огляду на специфічну поведінку логічних операторів **~&&~** та **~||~**, ми також ніколи не можемо бути абсолютно впевнені в результаті обчислення виразів, побудованих за їх допомогою.
Дійсно, якщо операнди виразу, побудованого за допомогою логічних операторів **~&&~** та **~||~**, мають різний тип даних, то який тип даних матиме результат?

~~~demo
> var x = 10, y = '***'
< undefined
> x && y
< '***'
> x || y
< 10
> typeof (x && y)
< 'string'
> typeof (x || y)
< 'number'
~~~

## ![ico-25 icon] Явне приведення типів⟪Explicit_type_coercion⟫

••Явне приведення типів даних дозволяє нам уникнути неоднозначності результату обчислення виразів.••

Найпростіший спосіб явного приведення даних довільного типу до типу ~string~, ~number~ або ~boolean~ — використання вбудованих однойменних функцій **~String()~**, **~Number()~**, **~Boolean()~**.

~~~demo
> Number('10')
< 10
> Number('***')
< NaN
> Number(undefined)
< NaN
> String(50)
< '50'
> String(false)
< 'false'
> String(undefined)
< 'undefined'
> Boolean('50')
< true
> Boolean(50)
< true
~~~

Спеціальне значення **~NaN~** (~Not a Number~) означає, що результат операції не є числом, але при цьому результат матиме тип **~number~**.

___________________________________________________________________

### ![ico-20 icon] Явне приведення до number⟪Explicit_type_coercion_to_number⟫

Арифметичні операції віднімання, множення, ділення та обчислення залишку від ділення завжди повертають результат типу **~number~**, але не факт, що цей результат буде числом.

Аналогічно, явне приведення до типу **~number~** за допомогою функції-конструктора **~Number()~** завжди поверне результат типу **~number~**, але не факт, що цей результат буде числом.

![ico-20 pin] Зверніть увагу, у яких випадках явне приведення до типу **~number~** за допомогою функції-конструктора **~Number()~** повертатиме **~0~**:

~~~demo
> Number(null)
< 0
> Number(false)
< 0
> Number('')
< 0
> Number(' ')
< 0
> Number([])
< 0
> Number([0])
< 0
> Number([''])
< 0
> Number([' '])
< 0
> Number('\n')
< 0
> Number('\t')
< 0
> Number('\r')
< 0
> Number('\v')
< 0
> Number('\f')
< 0
~~~

••Приведення «пробільних» символів до типу **_number_** завжди повертає 0.••

^^^[Пробільні символи]

^^До «пробільних» символів належать спеціальні символи з кодами:^^

| Symbol    | Code | Description |
| **~\t~**  |   9  | горизонтальна табуляція     |
| **~\n~**  |  10  | перехід на новий рядок     |
| **~\v~**  |  11  | вертикальна табуляція     |
| **~\f~**  |  12  | перехід на нову сторінку     |
| **~\r~**  |  13  | повернення каретки     |

^^У різних операційних системах для перенесення тексту на новий рядок використовуються різні комбінації символів **~\r~** і **~\n~**:^^
^^• **Windows**: Використовує пару символів **~\r~** + **~\n~**.^^
^^• **Linux / macOS**: Використовує лише символ **~\n~**.^^

^^^

Давайте розглянемо, у яких випадках явне приведення до типу **~number~** за допомогою функції-конструктора **~Number()~** повертатиме **~NaN~**:

~~~demo
> Number(undefined)
< NaN
> Number({})
< NaN
> Number(NaN)
< NaN
> Number('5 + 3')
< NaN
> Number('40px')
< NaN
> Number([5, 7])
< NaN
~~~

Функція-конструктор **~Number()~** приводить до типу **~number~** лише примітивні значення, тобто рядки, числа, логічні значення, **~null~**, **~NaN~**, **~undefined~**.
Движок обчислює значення виразу, що передається функції-конструктору **~Number()~** у круглих дужках. Якщо результат буде примітивним значенням, то це значення буде передано функції-конструктору **~Number()~**.
Якщо ж результат є масивом або об’єктом, то движок скористається **_вбудованим механізмом обчислення примітивного значення_** цього об’єкта.
За замовчуванням для отримання примітивного значення масиву або об’єкта вони приводяться до типу **~string~**, [►►► ^^але цю поведінку можна змінити^^ ►►►](page/value-of).

~~~demo
> String({})
< '[object Object]'
> Number('[object Object]')
< NaN
> String([5, 4, 8])
< '5,4,8'
> Number('5,4,8')
< NaN
~~~

Отже, функція-конструктор **~Number()~** приймає лише примітивні значення, тому движок спочатку перетворює вираз у круглих дужках функції-конструктора **~Number()~** на примітивний тип даних, а вже потім відбувається перетворення цього примітивного типу на тип **~number~**.

| **~x~**     | **~Number(x)~**       |
| ~number~    | **~x~**               |
| ~string~    | Якщо рядок містить лише цифри та роздільник розрядів, то результатом буде число, в іншому випадку — **~NaN~**.               |
| ~boolean~   | ~true~ → 1<br />~false~ → 0    |
| ~array~     | Масив приводиться до рядка: ~[a, b, c]~ → ~'a,b,c'~. Якщо масив порожній, то рядок буде порожнім. Далі див. вище приведення рядка до числового типу.               |
| ~object~    | Об’єкт приводиться до рядка ~'[object Object]'~, тому результатом приведення типів буде **~NaN~**.               |

![ico-25 hw] Тести

~~~tests
→→→ Number(57) | NaN, 57, undefined | 57 →→→
→→→ Number(4 * '8') | NaN, 32, 0 | 32 →→→
→→→ Number([8]) | NaN, 8, 0 | 8 →→→
→→→ Number([5] + [8]) | NaN, 13, 8, 5 | 13 →→→
→→→ Number(null - true) | NaN, null, true, 1, -1, 0 | -1 →→→
~~~

______________________________

Як ми переконалися, функція-конструктор **~Number()~** не є достатньо гнучкою для приведення рядків до типу **~number~**.

На щастя, у нас є більш гнучкі альтернативи.

#### ![ico-20 icon] parseInt & parseFloat⟪parseInt_&_parseFloat⟫

Для приведення до цілого числа або до числа з плаваючою комою (з десятковими знаками) можна використовувати вбудовані функції ~parseInt~ та ~parseFloat~.
На відміну від конструктора **~Number~**, ці функції аналізують рядок, навіть якщо в ньому є «лівобічні» символи після числа — ці символи просто будуть проігноровані:

~~~demo
> var sample = '3.14abc'
< undefined
> Number(sample)
< NaN
> parseFloat(sample)
< 3.14
> parseInt(sample)
< 3
> Number('3.14 / 5')
< NaN
> parseFloat('3.14 / 5')
< 3.14
> Number('3.14 * 5')
< NaN
> parseFloat('3.14 * 5')
< 3.14
~~~

Однак якщо рядок починається з символів, які не можуть бути зведені до числа, ці функції повернуть **~NaN~**.

### ![ico-20 icon] Явне зведення до ~boolean~⟪Explicit_conversion_to_~boolean~⟫

![ico-20 warn] У всіх наведених нижче випадках результат буде ~false~:

~~~demo
> Boolean('')
< false
> Boolean(0)
< false
> Boolean(-0)
< false
> Boolean(NaN)
< false
> Boolean(null)
< false
> Boolean(undefined)
< false
> Boolean(false)
< false
~~~

![ico-20 warn] У всіх інших випадках результат буде ~true~

При приведенні рядка до булевого типу діє просте правило:

якщо довжина рядка дорівнює 0, то повертається ~false~, в іншому випадку — ~true~

### ![ico-20 icon] Явне приведення до ~string~⟪Explicit_coercion_to_~string~⟫

~~~demo
> var str = String(5 + 8 + false)
< undefined
> str
< "13"
> var object = {}
< undefined
> String(object)
< "[object Object]"
> var array = [5, true, 'hello', 11]
< undefined
> String(array)
< "5,true,hello,11"
~~~

При приведенні числа до типу ~string~ можна використовувати метод **~toString()~**, який приймає один аргумент — десяткове число 2, 8 або 16 (система числення).
^^Десяткова система числення передбачається за замовчуванням, тому аргумент при цьому можна опустити.^^
^^Щоб отримати рядкове значення числа в двійковій системі числення, потрібно передати методу **~toString()~** аргумент 2, у вісімковій — 8, у шістнадцятковій — 16.^^

~~~demo
> Number(2).toString(2)
< "10"
> Number(58).toString(2)
< "111010"
> Number(8).toString(8)
< "10"
> Number(58).toString(8)
< "72"
> Number(16).toString(16)
< "10"
> Number(58).toString(16)
< "3a"
~~~
