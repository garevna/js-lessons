# ![ico-30 study] Приведение типов⟪pryvedenye_typov⟫

Тут ми потрапляємо на мінне поле, закладене динамічною типізацією. За винятком явних синтаксичних помилок, движок надає нам повну свободу у виразах, які ми доручаємо йому обчислювати, навіть якщо ці вирази виглядають як абсолютна нісенітниця.
Головна «міна» полягає в тому, що движок дозволяє використовувати у виразах дані різних типів і не розглядає це як помилку, якщо ви намагаєтеся додати число до рядка або до булевого значення. Тобто ви можете схрестити кактус із куркою, і движок вас не зупинить. Однак питання: а що вийде в результаті? Кактус чи курка?
Це й є головне питання, на яке ми спробуємо відповісти.

## ![ico-25 icon] Неявне приведення типів⟪Implicit_type_coercion⟫

Неявне приведення типів відбувається в процесі обчислення виразів.

•••• none
Головне, з чого слід починати: як движок обчислює наші вирази. А обчислює він їх послідовно, зліва направо, за винятком таких правил (пріоритетів):
![ico-20 warning] Якщо у виразі зустрічаються круглі дужки, то спочатку обчислюється вираз у круглих дужках, потім отримане значення підставляється замість виразу в круглих дужках. Тобто під час обчислення виразу _2 * (8 + 2)_ движок спочатку обчислить _8 + 2_, а потім — значення виразу **_2 * 10_**;
![ico-20 warning] Оператори множення та ділення мають вищий пріоритет, ніж оператори додавання та віднімання. Це означає, що під час обчислення виразу _5 + 8 * 2_ движок спочатку обчислить _8 * 2_, а потім — значення виразу **_5 + 16_**.
••••

![ico-25 hw] Тести

→→→ 40 / 2 * 5 | 100, 4 | 100 →→→
→→→ 40 / (2 * 5) | 100, 4 | 4 →→→
→→→ 10 - 2 * 5 + 4 | 44, 4 | 4 →→→
→→→ (10 - 2) * 5 + 4 | 72, 44, 4 | 44 →→→
→→→ (10 - 2) * (5 + 4) | 72, 44, 4 | 72 →→→

^^Перш ніж виконати присвоєння, движок повинен обчислити значення виразу в правій частині оператора присвоєння. Отримане значення буде присвоєно змінній, ім’я якої стоїть у лівій частині оператора присвоєння.^^

### ![ico-20 icon] Неявне приведення до типу string⟪Implicit_conversion_to_the_string_type⟫

Рядок домінує у виразі в тому сенсі, що кінцевий результат обчислення виразу завжди буде рядком, якщо у виразі зустрічається хоча б один рядок.

~~~js
20 + '5'  // '205'
'100' + 5  // '1005'
10 + '/' + 5  // '10/5'
~~~

Однак є винятки з цього правила. Наприклад, якщо рядок, що входить до виразу, бере участь як операнд у будь-якій арифметичній операції, крім операції **+**. Під час обчислення значення арифметичного виразу (~a - b~, ~a * b~, ~a / b~, ~a % b~) движок неявно приводитиме обидва операнди до типу number.

~~~js
20 - '5'  // 15
'100' - 5  // 95
'100' / '20'  // 5
'100' % '3'  // 1
~~~

Движок обчислює вираз послідовно, зліва направо, тобто якщо вираз починається з арифметичних операцій з числами, а потім додається рядок, то спочатку будуть виконані арифметичні операції, а потім до отриманого числа буде додано рядок, що перетворить результат на рядок.

~~~js
20 + 5 + '5'  // 255
'100' - 5 + 'px' // '95px'
100 / '20' + 5 + ''  // '10'
~~~

◘◘![ico-25 cap] **1**◘◘

~~~js
var height = 72
var padding = 20
var illegal = 'height: ' + height + padding * 2 + 'px'
var legal = 'height: ' + (height + padding * 2) + 'px'
~~~

~~~js
illegal // 'height: 7240px'
legal  // 'height: 112px'
~~~

![ico-25 hw] Тести

→→→ 2 - '10' + '8' | '0', 0, '-88' | -88 →→→
→→→ 2 + '10' - '200' | 2, 10, '210' | 10 →→→
→→→ '5' + '20' / '20' | 0, 20, '51' | 51 →→→
→→→ '5' - '20' / '20' | '5', '20', 0, 4 | 4 →→→
→→→ ('5' - '2') * '10' | 30, -15, 0 | 30 →→→
→→→ '5' - '2' * '10' | 30, -15, 10 | -15 →→→

### ![ico-20 icon] Масив як операнд арифметичного виразу⟪An_array_as_an_operand_in_an_arithmetic_expression⟫

Перетворити результат обчислення виразу на рядок можна не лише шляхом явного додавання операнда типу string. Наприклад, додавання порожнього масиву дає той самий результат. Тобто якщо масив виступає операндом у виразі, то він перетворюється на рядок.

~~~js
20 + 5 + []      // '25'
20 + 5 + [0]     // '250'
20 + 5 + [0, 5]  // '250,5'
~~~

Тому, якщо масив виступає операндом арифметичної операції (множення, ділення, віднімання, обчислення залишку від ділення), ситуація дещо інша: якщо масив порожній, його приводять до порожнього рядка, який, будучи операндом арифметичної операції, приводять до 0. Якщо масив містить один елемент, то цей елемент зводиться до рядка, а далі — до числового типу (число або ~NaN~).

~~~js
20 + '5' - []     // 205
20 + '5' - [3]    // 202
20 + '5' - ['5']  // 250
20 + '5' - [3, 0] // NaN
~~~

![ico-25 hw] Тести

→→→ 5 + [8] | 13, '58' | 58 →→→
→→→ 5 * [8] | 40, NaN, 0 | 40 →→→
→→→ '5' % ['8'] | 0, NaN, 5 | 5 →→→
→→→ 5 * [8, 0] | 40, NaN, 0 | NaN →→→
→→→ ['8'] - '5' | 3, NaN, 0 | 3 →→→
→→→ [] + false | 'false', NaN, 0 | false →→→
→→→ [4] + NaN | '4NaN', NaN, 0 | 4NaN →→→

















Однак якщо перед масивом використати будь-який знак арифметичної операції, то масив перетворюється на число (або ~NaN~):

◘◘![ico-25 cap] **2**◘◘

~~~js
+['8'] + 5    // 13
null + +[4]   // 4
+[5] + null   // 5
~~~

### ![ico-20 icon] Неявне приведення до типу number⟪Implicit_coercion_to_the_number_type⟫

Неявне приведення до типу ~number~ відбувається в арифметичних виразах:

~~~js
var  x = '8' / 2
~~~

^^(значенням змінної ~ x~ буде 4).^^

![ico-20 warn] При участі в арифметичних операціях порожній рядок (~""~) і порожній масив (~[]~) перетворюються на **0**:

~~~js
var x = ''
var y = x / 5
~~~

^^(вираз ~"" / 5~ буде приведено до ~0 / 5~).^^

~~~js
console.log(+'')         // 0
console.log(+[])         // 0
console.log(+[]+'')      // 0
~~~

![ico-20 warn] Якщо в арифметичному виразі беруть участь спеціальні значення ~undefined~ або ~null~, то вони перетворюються на число таким чином:

~~~js
Number(undefined)   // NaN
Number(null)        // 0
~~~

![ico-20 warn] Якщо в арифметичному виразі беруть участь логічні значення ~true~ або ~false~, то вони перетворюються на число так:

~~~js
var a = false
var b = true
var z = a + b    //  0 + 1 --> 1
~~~

![ico-20 warn] Окрім арифметичних операцій, перетворення до типу ~number~ відбувається за участю змінної в операціях порівняння (за винятком операцій ~===~ та ~!==~, коли порівнюються не лише значення, а й типи даних)

____________________________________________________________

![ico-25 cap] ** 3**

~~~js
a = false, b = undefined
a > b       // 0 > NaN  --> false
a < b       // 0 < NaN  --> false
a == b      // 0 == NaN --> false
~~~

![ico-25 cap] ** 4**

~~~js
a = true,  b = null
a > b       // 1 > null   --> true ( 1 > 0 )
a < b       // 1 < null   --> false
a == b      // 1 == null  --> false
~~~

### ![ico-20 icon] Неявне приведення до типу boolean⟪Implicit_coercion_to_the_boolean_type⟫

Приведення до логічного типу (~boolean~) відбувається в умовних операторах (~if~, тернарний оператор)

![ico-25 cap] **5**

~~~js
if ('5') console.log('Yes')
~~~

Обчислюватиметься логічне значення виразу в круглих дужках оператора ~if~, тобто «під капотом» буде виконана операція

~~~js
Boolean('5')
~~~

![ico-20 warn] Під час виконання логічних операцій ~&#10072;&#10072;~ та ~&&~ відбувається неявне приведення типів операндів до логічного значення, але при цьому результатом логічної операції буде початкове значення одного з операндів, навіть якщо воно не є булевим

_______________________________________________

#### ![ico-20 icon] &&⟪&&⟫

^^^[Операція&nbsp;&&]

Операція ~&&~ перебирає операнди зліва направо, приводячи їх до логічного значення, доки не зустрінеться перший ~false~

у цьому випадку повертається початкове значення останнього операнда

![ico-25 cap] **6**

~~~js
true && false && null   //  false
true && '5' && null     //  null
true && [] && null      //  null
~~~

![ico-25 cap] **7**

~~~js
true && ![] && null     //  false
~~~

^^обчислюється значення другого операнда ~![]~, воно дорівнюватиме ~false~, операція зупиняється і повертається останній операнд, на якому зупинилися^^

~~~js
true && true && true && true     //    true
~~~

^^дійшли до кінця, але не зустріли ~false~, повертається останній операнд^^

^^^
__________________________________________________________________

#### ![ico-20 icon] ||⟪__⟫

^^^[Операція ||]

Операція ~||~  перебирає операнди зліва направо, приводячи їх до логічного значення, доти, доки не зустрінеться перший ~true~

у цьому випадку повертається початкове значення останнього операнда, на якому зупинилися

~~~js
null || false || 5 || ''          //   5
null || '' || 0 || 4 || 10        //   4
null || false || undefined || ''  //  ""
~~~

^^послідовно обчислюються логічні значення^^

^^• першого операнда (~null~) — це ~false~,^^
^^• другого операнда — ~false~,^^
^^• третього операнда (~undefined~) — це ~false~,^^
^^• четвертого операнда (~""~) — це ~false~^^

^^більше операндів немає, операція завершується і повертає останній операнд, на якому зупинилася (~""~)^^

^^^

#### ![ico-20 icon] !!⟪!!⟫

^^^[Операція !!]

можна звести змінну будь-якого типу до ~boolean~ за допомогою логічної операції подвійного заперечення:

~~~js
var x = null
var y = !!x        // false

var x = undefined
var y = !!x        // false

!![]              // true
!!+[]             // false
~~~

^^^
